# MySQL Metadata Provider Module

MySQL-protocol metadata provider used for optional metadata-aware DeltaScope audits against MySQL and TiDB.

## Files

| File | Responsibility |
|------|---------------|
| provider.go | Opens MySQL-compatible metadata connections and loads normalized dialect, schema, instance-fact, and target-table snapshot data from information schema, including preserved per-index cardinality facts and per-member plain-key knownness (`SUB_PART`/`COLLATION` plus NULL `COLUMN_NAME` classification into `PrefixParts`/`DescParts`/`UnmodeledKeyParts`/expression marks). Instance facts carry explicit known bits: MySQL reads `innodb_page_size` and `innodb_large_prefix` (5.7), TiDB banners additionally read the `max-index-length` and `alter-primary-key` tidb-server configs via `SHOW CONFIG`, verifying every matching row (one per tidb-server instance): disagreeing, unparsable, non-positive, or absent values stay unknown, while query/scan/iteration failures propagate as provider errors rather than degrading into gaps (issue #83 T04-B/R2, issue #89 T10-R3 — `alter-primary-key` is the config fact `int_only` clustered mode defers to). Expression members read the same `COLLATION` direction fact column members do — `D` lands `Descending`, `A` stays ascending, and an unproven or unrecognized direction leaves the member unmodeled rather than guessing ascending (issue #89 T10-R3). Column rows carry T07 advanced facts from the same COLUMNS select: `GENERATION_EXPRESSION` plus `EXTRA` tokens yield generated storage + expression facts (`VIRTUAL`/`STORED GENERATED`), `DEFAULT_GENERATED` yields parsed expression-default facts with verbatim `DefaultValue` bytes preserved plus `DefaultParenthesized=true` (catalog-stored expression defaults are always parenthesized syntax), and `INVISIBLE` yields effective visibility (absence on a complete row = effective visible; the catalog never proves `VisibilityExplicit`). Undecodable catalog expression text stays an explicit unknown fact via `ParseCatalogExpressionFacts` (issue #86 T07). The T08-R1/R2 `DefaultLiteral` identity fact carries the verbatim decoded `COLUMN_DEFAULT` bytes with a kind domain from the column's own base type (parameters/attributes stripped; numeric bases → `numeric`, else `string` — the recorded encoding is the catalog's own, e.g. scale-normalized `1.00`, and cross-source comparability is the rule's domain check), `DefaultIsCurrentTimestamp` asserts only on temporal base types (`timestamp`/`datetime`, including parameterized forms), and expression/temporal defaults never carry a literal identity (issue #87 T08-R1). T10 adds an `information_schema.STATISTICS.IS_VISIBLE` capability probe (a backticked `information_schema`.`columns` existence check counted in provider call totals): on capable catalogs (MySQL 8.x, TiDB) the index select carries the column and each named member lands effective `Visibility` (`YES`→visible/`NO`→invisible), while uncapable catalogs (MySQL 5.7 or a zero-count probe) omit the column and leave member visibility empty — a real probe failure propagates as a load error rather than degrading into a guessed shape; `INDEX_TYPE` also classifies `SPATIAL`/`FULLTEXT` into `spec.Index.Kind` (issue #89 T10). T10-R1 adds member-level facts: an `EXPRESSION` capability probe selects the catalog's functional key-part text (parsed into `ExpressionFacts` + multi-valued marks via `ParseCatalogExpressionFacts`/`CatalogExpressionIsMultiValued`), members accumulate into `spec.Index.KeyParts` (ordinal, kind, column, prefix length, descending, expression identity), `information_schema.PARTITIONS` loads `Partitioned` (an unanswerable probe keeps the fact unknown rather than guessing false), and TiDB's `information_schema.TIDB_INDEXES.CLUSTERED` plus the single-integer member shape resolves `PrimaryKeyIsHandle` (STATISTICS synthesizes a PRIMARY row even for handle tables, so index presence alone cannot prove an operable PRIMARY object — a missing CLUSTERED row or unmatchable member shape now sets `PrimaryKeyHandleUnknown` rather than defaulting the object into existence), and the TiDB instance-fact probe additionally reads the `tidb_enable_clustered_index` session variable so declared-but-unstated primary keys resolve through the observed mode (empty means unprobed → the handle answer stays unknown; never populated on MySQL). R2 fixes member classification for TiDB's literal-`'NULL'` `COLUMN_NAME` on expression members: SQL NULL or literal-with-expression-text stays an expression member, a literal matching a loaded real column name stays a plain column (a backticked `` `NULL` `` column is legal MySQL), and neither-provable stays `UnmodeledKeyParts` (issue #89 T10-R2) |
