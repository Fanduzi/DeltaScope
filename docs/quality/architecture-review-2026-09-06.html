之后 — 一个 deep module，薄 adapter

Transport Connection Resolution
TLS · timeout · PG 端口 · MySQL/TiDB catalog 别名 · 有界错误分类

adapter 仍负责打开/关闭，以及各自的 exit/status 文案。audit 连接池 opener 和钉住的 Online Query Access Session opener 继续分开。

问题
CONTEXT.md 已经命名了 Transport Connection Resolution，但现有 module 是 shallow 的：只做 password 和 host。TLS、timeout 零值语义、PostgreSQL 默认端口、MySQL/TiDB catalog 别名，从三个组装器里漏出去。CLI 还在注入自定义 metadata opener；HTTP 和 MCP 已经走 auditmeta.Prepare。

做法
加深一个 module，让它拥有连接输入、TLS、timeout、catalog 别名和有界错误分类。CLI / HTTP / MCP 只做 flags、connection_id、connection_ref 的薄 adapter。不要把 audit 连接池 opener 和钉住的 Query Access opener 合成一个。

  • Wins
  • · locality：TLS 只分类一次
  • · leverage：catalog 别名只有一条路径
  • · CLI opener 收进 auditmeta
  • · MCP 不再缺 TLS
  • · 测试打在一个 resolution interface 上
只有在统一对外错误文案时，才会和 CLI 的 TLS / 端口 ADR 冲突。不要统一文案。那些 ADR 冻结的是 adapter 面向用户的句子，不是 TLS 加载写三份。online.MapOnlineError 已经自称共享 seam，但 CLI 和 MCP 并没有走它。

问题
CONTEXT.md 已经拆开 Rule Catalog、Default Policy、Loaded、Suppression。运行时又各算一遍：catalog 方言靠 ID 字符串，configstatus 的 Loaded 不走 Register，skipped-rule 理由看起来像第五个同类事实。这周的 bug 是命名撞车，不是缺功能。

做法
一个 module 通过一个 interface 回答这四个事实。展示用 adapter 只渲染，不算第二遍。Skipped 仍是运行时的另一件事。不要把四个名字并成一个。

  • Wins
  • · locality：Loaded 只有一个主人
  • · leverage：发现和 status 共用
  • · configstatus 不再重放 Register
  • · 方言启发式离开 catalog
和 2026-09-04 的「公开信号必须具名拆开」兼容：事实继续分开。加深的是计算的 locality，不是把 Catalog 并进 Loaded。2026-06-14 禁止从 explain/audit 反推 status —— 专门的 module 才是主人，不是第二套重算。

之后 — completeness 进 Audit

parse / extract / evaluate（内部）
incomplete-audit completeness 一套扫描 · diagnostics · review floor · unaudited 视图
output adapter 消费这个视图

问题
「有界语句没走进 evaluation」是一件事：Verdict 不能是 pass，diagnostics 是 audited=false，调用仍然报错。它散在两套 SQL 扫描、导出的 Parse/Extract、markdown adapter 并不拥有的 CLI 外包、以及 CI adapter 去匹配字符串 parser_error。JSON output adapter 没人用；CLI JSON 是另一套视图。

做法
把 Parse/Extract 藏起来。review floor 留在 Audit。completeness 只保留一套内部 implementation：扫描、diagnostics、unaudited 视图。output adapter 渲染这个视图。删掉没人用的 JSON adapter。

  • Wins
  • · locality：引号扫描只有一套
  • · interface 是 Audit，不是阶段
  • · Markdown 自己拥有 diagnostics
  • · CI 不再字符串匹配
  • · 删掉死掉的 JSON adapter
completeness ADR 已经规定 floor 只在 application 做一次。不要在 adapter 里再 floor。各 surface 的测试保留；它们应该打 Audit，而不是自己拼 pass + parser_error 夹具。

问题
spec.DML.Tables 实际表示 mutation target，不是 FROM/JOIN 来源。这个约定在两个 parser adapter、metadata enrichment、target 推断、existence rule 里各重述一遍。PostgreSQL 抽取从不选择 joined UPDATE/DELETE 的 target；rule 又按 MySQL/TiDB 门控，所以这条 leak 在 PostgreSQL 上是静默的。

做法
把 mutation target 做成 statement spec 上的具名事实。parser adapter 填它。metadata、auditmeta、existence rule 读它。Tables 如果还有人要「提到过的 relation」，可以留着。

  • Wins
  • · locality：target 身份只活一处
  • · interface 就是测试面
  • · PG 缺口变得可见
2026-08-30 的 DML table existence 要求 SDK/CLI/HTTP/MCP 测试。这些测试留着。加深的是 spec 上的事实，不是删掉 surface 证据。

问题
统一入口之后，transport 仍会打开 online session、丢掉 Observed Server Identity，然后 SDK 再 ping、再 identify。版本 sentinel 也有两个：online.ErrPostgreSQLQueryAccessVersionUnsupported 和 deltascope.ErrOnlineQueryAccessPostgreSQLVersionUnsupported。CLI 映射前者，HTTP 构造映射后者。

做法
打开/关闭仍归 transport。Online Query Access Session 从已经 identify 过的 conn 构建，Observed Server Identity 只观察一次。

  • Wins
  • · locality：identity 探测一次
  • · 版本 sentinel 只有一个
  • · 钉住的连接不再第二次 ping
2026-08-12 要求 SDK 从调用方拥有的 *sql.Conn 构造，transport 拥有打开/关闭。第二次 Identify 是落地残留，不是合同要求。不要把 open 搬进 SDK。
