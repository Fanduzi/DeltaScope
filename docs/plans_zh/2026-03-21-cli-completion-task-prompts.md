# CLI 补完任务提示词

> 用于 `CLI Completion` 里程碑的逐任务实施与评审。
> 每个提示词都假设工作发生在 `/Users/fan/GolangProjects/deltascope` 中。

## 全局规则

- 在未提供连接输入时，保持现有离线审计行为稳定。
- 通过 CLI 参数暴露元数据感知审计，而不是隐藏在仅配置文件可用的接线中。
- 在可行范围内，让 CLI 对 MySQL 用户保持熟悉感。
- 保持规则执行与规则目录元数据为两个通过 `rule_id` 关联的独立关注点。
- 对每个非平凡命令、链路或 UX 变更使用 TDD。
- 将 `three-level-doc` 视为硬门槛。
- 每个任务都返回变更文件、运行测试、状态和 commit hash。

## 里程碑重点

- 元数据感知 CLI 审计
- 类 MySQL 的连接体验
- 规则目录发现命令
- 配置校验与默认配置查看
- 稳定的能力报告
- CLI help、错误与输出补完

## 任务意图

### 任务 1：规划工件

- 保存该里程碑的设计、实施计划与提示词。
- 让命名与范围与已批准命令面保持一致。

### 任务 2：公共与 application 请求链路

- 暴露 CLI 所需的元数据感知审计输入，同时不破坏离线路径。
- 为下游调用方保持稳定的公共 API 形状。

### 任务 3：连接参数与密码 UX

- 增加类 MySQL 连接参数。
- 支持无回显密码提示。
- 清晰处理互斥与非法参数组合。

### 任务 4：元数据接线与 schema 解析

- 根据 CLI 输入构造元数据 provider。
- 尽可能自动推断 schema。
- 当 schema 解析有歧义或无法完成时，诚实失败。
- 在在线模式下自动检测方言，并校验显式覆盖值。

### 任务 5：规则目录元数据

- 增加足够的规则元数据，使 CLI 能解释已发布规则。
- 不仅有 ID，还要包含示例与配置指导。

### 任务 6：规则命令

- 交付 `rules list`、`rules show` 与 `rules search`。
- 让 `rules show` 足够有用，使用户无需查看源码来找示例。

### 任务 7：配置命令

- 交付 `config lint` 与 `config show-default`。
- 清楚区分 `config init` 与 `config show-default`。

### 任务 8：能力命令

- 从 CLI 暴露 DeltaScope 能做什么的精简摘要。
- 包含离线/元数据感知模式区别。

### 任务 9：CLI UX 收口

- 收紧 help 文本、示例、quiet 输出、JSON 细节与用户可见错误。
- 在中英文文档中同时记录离线与在线用法。

### 任务 10：最终收口

- 重新运行完整验证。
- 更新 handoff、autonomous progress 与 decisions。
- 让 CLI 里程碑处于可发布状态。
