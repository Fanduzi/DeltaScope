# DeltaScope 完成 Create-Table 超集设计

## 目标

完成离线 `CREATE TABLE` 规则表面，使其在广度、结构和可用性上明显超越 `gAudit`。

## 当前状态

`DeltaScope` 已经覆盖了强大的核心：

- 表注释/名称/基本选项检查
- 主键存在性和语义
- 审计列
- 列注释/默认值/not-null/float-double/varchar 规则
- create-table 索引数量/前缀/重复检查
- 对象形状禁止如外键、分区、`LIKE` 和 `AS SELECT`

剩余的主要 create-table 差距是聚焦于广度而非架构：

- 标识符和关键字检查
- 更深入的类型族允许/禁止规则
- 字符集/排序规则指导
- 更强的冗余索引分析
- 一些剩余的表选项和对象形状细节

## 推荐方向

将此里程碑视为有意图的广度推进。除非立即在多个规则族中产生回报，否则避免发明新的重大抽象。复用现有的 create-table 解析器中立提取和 DDL 规则框架。

## 需要完成的规则族

- 标识符合法性和保留关键字治理
- 更广泛的类型族策略：
  - blob/json/bit/timestamp 族决策
  - `char` vs `varchar` 指导
- 列字符集/排序规则限制（静态可用时）
- 超越精确重复的更深入冗余索引分析
- 值得离线完成的剩余表选项和对象形状检查

## 非目标

- 实时 schema 存在性检查
- HTTP API 或 MCP 工作
- 当前 create-table 规则框架的广泛重新设计

## 预期结果

此里程碑后，`CREATE TABLE` 不应再是"强大但不完整"。它应该是相对于 `gAudit` 的明确离线 create-table 超集，使下一个产品级里程碑可以自由地转向服务交付或剩余横切 DDL 清理。
