# T13 native probe archive

Each archive records the exact SQL, rc, error output, and post-state
reads its steps produced on the four frozen anchors (mysql 5.7.44 /
8.0.46 / 8.4.10, tidb v8.5.0). Scope notes record what each log
actually proves — read the log text, not this file, for evidence.

| Archive | Scope |
|---|---|
| `p1_all.log` (`probe.sh`) | DROP/TRUNCATE on RANGE fixtures, `TRUNCATE ALL`, DROP on a non-partitioned table (1505), missing-member DROP (1507), drop-all (1508). |
| `p2_exchange.log` (`probe2.sh`) | EXCHANGE data movement, missing counterpart (1146), partitioned counterpart (1732), definition-mismatched counterpart (1736), missing member (1735), EXCHANGE on a non-partitioned primary (1505). |
| `p3_validate_mixed.log` (`probe3.sh`) | WITH/WITHOUT VALIDATION arms on MySQL anchors and the mixed-action refusals. **Contaminated cell:** the `absent`-validation arm ran after the WITHOUT arm had already emptied the counterpart, so its "absent → rc=0" line proves nothing about default validation — superseded by `p5_validation_arms.log`. The `t13m parts` line printed by that run executed `true`, not a catalog query — it is not post-state evidence. |
| `p4_nonpart.log` (`probe4_nonpart.sh`) | TRUNCATE PARTITION and EXCHANGE PARTITION on non-partitioned tables → 1505 on all four anchors (T13-R1 cells the p1/p2 archives lacked). |
| `p5_validation_arms.log` (`probe5_validation_arms.sh`) | Three-arm rerun with an identical violating fixture reset per arm. **Valid scope is MySQL only:** absent clause refuses violating rows exactly like `WITH VALIDATION` (MySQL 1526); only `WITHOUT VALIDATION` lands the row. Corrects the p3 absent cell. The entire TiDB section recorded `1049 Unknown database 'golden'` (the anchor DB was missing) — no TiDB arm ever reached the table; superseded by `p10_tidb_validation_arms.log`. |
| `p5_validation_tidb_post.log` | **Incomplete** TiDB arm supplement: the DDL outcomes are real (`WITH VALIDATION` and absent clause → 1737, `WITHOUT VALIDATION` → rc=0) but every post-state row dump is empty — the driver lost query output, so no row landing is proven. Superseded by `p10_tidb_validation_arms.log`. |
| `p6_mixed_matrix.log` (`probe6_mixed_matrix.sh`) | Mixed-action matrix: partition+structural sibling refusals (MySQL 1064 / TiDB 1064-or-8200 by order), `ALGORITHM=INPLACE` + DROP PARTITION (executes on 8.0/8.4/TiDB, refused 1846 on 5.7), HASH-type DROP (1512) vs TRUNCATE/EXCHANGE (execute). |
| `p7_modifiers.log` (`probe7_modifiers.sh`) | Modifier narrowing: `ALGORITHM=DEFAULT`/`LOCK=DEFAULT` + DROP execute on all anchors; modifiers after the partition action are syntax errors. `ALGORITHM=INPLACE` + TRUNCATE/EXCHANGE arms are covered by p11, not this log. |
| `p8_tableoption.log` (`probe8_tableoption.sh`) | `ENGINE=InnoDB` mixed with `DROP PARTITION`. MySQL observed the option-first order only (table option before the action) → 1064 near `PARTITION p0` on all three anchors; the partition-first order was never sent to MySQL. TiDB observed both orders: option-first → 8200 (unsupported multi schema change), partition-first → 1064. Upgrades the table_option sibling cell from unprobed to proven-refused. |
| `p9_engine_exchange.log` (`probe9_t13r2.sh`) | B4 engine premise: MyISAM counterpart against an InnoDB partitioned table refuses 1497 on MySQL 5.7/8.0/8.4; InnoDB counterpart executes. TiDB accepts `ENGINE=MyISAM` but normalizes the catalog label to InnoDB (observed via a successful `information_schema.TABLES` read) and executes — the engine-mismatch dimension is MySQL-only. **The appended `SELECT TABLE_NAME, COUNT(*)` post-DDL queries failed on every anchor (1054 on MySQL, 8123 on TiDB) and are not evidence — the log supports only the DDL and engine-label observations.** |
| `p10_tidb_validation_arms.log` (`probe10_tidb_validation.sh`) | D1: complete TiDB three-arm re-run — each arm rebuilds the same fixture independently (create → seed → violating counterpart row → catalog + both-side rows before/after). absent and `WITH VALIDATION` refuse 1737 keeping the row on the counterpart; `WITHOUT VALIDATION` executes and the row lands in `t13v`. Supersedes the 1049-contaminated TiDB section of `p5_validation_arms.log` and the incomplete `p5_validation_tidb_post.log`; originals preserved. |
| `p11_subpartition_interval_bounds_inplace.log` (`probe11_t13r2.sh`) | A2/A3/D2: MySQL subpartitioned catalog lists leaf names in `SUBPARTITION_NAME`; leaf EXCHANGE executes, top-level EXCHANGE refuses 1734 (5.7/8.0/8.4). TiDB normalizes the subpartition clause away — leaf name refuses 1735, top-level executes. TiDB `RANGE INTERVAL` materializes `P_LT_*` catalog names; named TRUNCATE executes. `PARTITIONS 18446744073709551615` and `PARTITIONS 8193` both refuse 1499 on 8.0.46. `ALGORITHM=INPLACE, TRUNCATE PARTITION` and `ALGORITHM=INPLACE, EXCHANGE PARTITION` execute on all four anchors. |
| `p12_exchange_effective_types.log` (`probe12_t13r3.sh`) | T13-R3 B-group: EXCHANGE effective-type pairs on mysql80 + mysql57, one rebuilt fixture pair per arm. Executes: `DECIMAL(12)`↔`DECIMAL(12,0)`, `DECIMAL`↔`DECIMAL(10,0)`, `DECIMAL(12) UNSIGNED`↔`DECIMAL(12,0) UNSIGNED`, `INT(10)`↔`INT(11)`. Refuses 1736: `DECIMAL(12,1)`↔`DECIMAL(12,0)`, `DECIMAL(11)`↔`DECIMAL(12)`, `DECIMAL(12)`↔`DECIMAL(12) UNSIGNED`. Each arm records DDL rc plus a catalog `COLUMN_TYPE` read per side — no post-state row claims. |
