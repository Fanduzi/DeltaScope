# Decision: v0.242.0 Release Recovery CI Polish

Date: 2026-06-01
Status: Accepted
Related milestone/version: v0.242.0
Related commits: `0e3f31c` (GH_TOKEN preflight fix on main), v0.242.0 release commits
Related tests: `make release-recovery-contract-test`
Related docs: `docs/dev/release-recovery.md`, `docs/dev/testing.md`

## Context

v0.241.0 shipped a release recovery dry-run patch. After tagging v0.241.0 (`1d91035`), a dry-run dispatch revealed that the preflight step was missing `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`, causing `gh release download` to fail with an authentication error. The fix (`0e3f31c`) was committed to main but is not included in the v0.241.0 tag.

## Decision

1. **v0.241.0 tag is not moved.** The tag points to `1d91035` and remains the published v0.241.0 release. Tag immutability is a core project invariant.
2. **v0.242.0 starts from `0e3f31c`.** The GH_TOKEN fix is the first commit after v0.241.0 and becomes the formal content of v0.242.0.
3. **A regression gate is added.** `make release-recovery-contract-test` now statically checks that `GH_TOKEN` wiring exists in the recovery workflow. If removed in a future edit, the gate fails.
4. **No product-facing changes.** v0.242.0 changes only release CI tooling and documentation. SQL audit behavior, parser support, audit rules, and parser_error counts are unchanged.

## Rationale

- Moving tags is destructive and violates the project's release integrity model.
- The gap was auth wiring only; no release artifacts were affected because v0.241.0 was published by the full `release.yml` workflow (which has its own GH_TOKEN).
- A static grep gate is the simplest, most durable way to prevent this specific regression.

## Public Contract

- `make release-recovery-contract-test` now includes a `GH_TOKEN` wiring check.
- v0.242.0 is the first tagged release where the recovery workflow preflight is known to work correctly with `gh release download`.

## Deferred / Out Of Scope

- No parser support added.

- No parser_error count reduction.
- No DDL census change.
- No PG ALTER TABLE rule count change.
