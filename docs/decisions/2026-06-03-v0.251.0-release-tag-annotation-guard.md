# v0.251.0 Release Tag Annotation Guard

**Date:** 2026-06-03
**Status:** committed

## Decision

Add a release tag annotation guard that prevents lightweight tags from passing through the release pipeline. All future release tags must be annotated (`git tag -a`).

## Context

Post-release review flagged that release tag annotation type was not verified anywhere in the release pipeline. Investigation showed v0.250.0 is annotated (object type `tag`), but the gap remained: nothing enforced this for future releases.

## Guard Contract

1. **`scripts/verify_release_tag_annotation.py`** — standalone script that checks a local tag's git object type:
   - `tag` → PASS (annotated)
   - `commit` → FAIL (lightweight)
   - missing → FAIL
2. **`scripts/test_verify_release_tag_annotation.py`** — offline tests using temporary git repos.
3. **`make release-tag-annotation-test`** — runs unit tests (no tag required).
4. **`make release-tag-annotation-gate VERSION=vX.Y.Z`** — verifies an existing tag is annotated (post-tag only).
5. **`.github/workflows/release.yml`** — early guard step in `release-linux` job fails the build if the triggering tag is lightweight.

### Pre-release vs Post-tag Verification

- Pre-release: only `release-tag-annotation-test` can run (tag does not exist yet).
- Post-tag: `release-tag-annotation-gate` and the workflow guard enforce annotated tags.

## Non-Goals

- No tag rewrite for any published tag.
- No release rewrite.
- No SQL audit behavior change.
- No parser/rule/policy/output change.
- No npm/Homebrew behavior change.

## Verification

- `python3 scripts/test_verify_release_tag_annotation.py` — 10/10 tests pass.
- `make release-tag-annotation-test` — OK.
- Workflow guard runs before GoReleaser and all artifact publishing steps.
