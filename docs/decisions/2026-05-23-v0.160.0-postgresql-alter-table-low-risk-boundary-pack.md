## Context

v0.150.0 left 7 `unsupported_boundary` and 4 `parser_error` in the PostgreSQL ALTER TABLE residual census (66 total cases). The 7 unsupported boundaries span 3 families: `column_attributes` (2), `constraints` (3), and `table_properties` (2).

v0.160.0 targets the low-risk subset: 2 FK deferrability changes (promote to finding_covered) and `SET WITHOUT OIDS` (normalize silent). The remaining 4 unsupported boundaries and all 4 PG18 parser errors are deferred.

### Parser Dependency

Current parser: `github.com/pganalyze/pg_query_go/v6 v6.2.2`, backed by libpg_query 17. PG18 parser-error forms remain out of scope pending `pg_query_go v7`.

## AST Census Results

All 7 candidates parse successfully. 6 produce `AlterTableStmt`; 1 produces `AlterTableMoveAllStmt`.

| # | SQL | Subtype | Def Kind | Identity | Payload Risk |
|---|-----|---------|----------|----------|-------------|
| 1 | `SET EXPRESSION AS (...)` | `AT_SetExpression` | `AExpr` | column in cmdName, expression in def | **high** — expression body inseparable |
| 2 | `ADD GENERATED BY DEFAULT AS IDENTITY` | `AT_AddIdentity` | `Constraint(CONSTR_IDENTITY)` | column in cmdName, constraint def present | **medium** — sequence options in constraint body |
| 3 | `EXCLUDE USING gist (...)` | `AT_AddConstraint` | `Constraint(CONSTR_EXCLUSION)` | constraint in def.conname, columns/operators in exclusions | **high** — operator classes inseparable |
| 4 | `ALTER CONSTRAINT ... DEFERRABLE` | `AT_AlterConstraint` | `Constraint(CONSTR_FOREIGN)` | constraint in cmdName, deferrable flag in def | **low** — boolean flag only |
| 5 | `ALTER CONSTRAINT ... INITIALLY DEFERRED` | `AT_AlterConstraint` | `Constraint(CONSTR_FOREIGN)` | constraint in cmdName, initially_deferred flag in def | **low** — boolean flag only |
| 6 | `SET WITHOUT OIDS` | `AT_DropOids` | (no def) | table only, no payload | **none** — pure table-only action |
| 7 | `ALL IN TABLESPACE ... SET TABLESPACE ...` | `AlterTableMoveAllStmt` | (separate path) | tablespace names only | **low** but different parser path |

### Key AST Discoveries

1. **ALTER CONSTRAINT DEFERRABLE / INITIALLY DEFERRED**: Both use `AT_AlterConstraint` with `def` containing a `Constraint` node of type `CONSTR_FOREIGN`. The constraint name is in `cmdName`, the table is in `atStmt.relation.relname`. The `deferrable` and `initdeferred` boolean fields are directly readable. No expression or column list is involved — this is a pure attribute change on an existing FK constraint.

2. **SET WITHOUT OIDS**: `AT_DropOids` with `hasDef=false`. Table-only action with no payload. Obsolete since PG12 (OIDs removed from user tables). Safe to normalize silently.

3. **ALL IN TABLESPACE**: Parses as `AlterTableMoveAllStmt`, not `AlterTableStmt`. Different top-level node requires a separate extraction path. Deferred.

## Decision

### Promote to Finding-Covered

Two FK deferrability changes — low payload risk, clean identity extraction.

| # | SQL | Action | Rule ID | Level |
|---|-----|--------|---------|-------|
| 1 | `ALTER TABLE orders ALTER CONSTRAINT orders_user_id_fkey DEFERRABLE` | `alter_constraint_deferrable` | `ddl.pg.alter.constraint_deferrable.notice` | notice |
| 2 | `ALTER TABLE orders ALTER CONSTRAINT orders_user_id_fkey INITIALLY DEFERRED` | `alter_constraint_initially_deferred` | `ddl.pg.alter.constraint_initially_deferred.notice` | notice |

### Normalize Silent

One obsolete form — no audit value.

| # | SQL | Action | Rule ID | Classification |
|---|-----|--------|---------|----------------|
| 1 | `ALTER TABLE users SET WITHOUT OIDS` | `set_without_oids` | (none) | `normalized_silent` |

### Defer

Four unsupported boundaries and four PG18 parser errors.

| # | Candidate | Reason |
|---|-----------|--------|
| 1 | `SET EXPRESSION AS (...)` | Expression body inseparable from identity |
| 2 | `ADD GENERATED ... AS IDENTITY` | Sequence options in constraint body |
| 3 | `EXCLUDE USING gist (...)` | Operator classes and predicate inseparable |
| 4 | `ALL IN TABLESPACE ...` | Separate `AlterTableMoveAllStmt` parser path |
| 5-8 | PG18 parser_error forms (4) | Blocked on `pg_query_go v7` |

### Forbidden Metadata

The following must NEVER appear in finding metadata:

| Forbidden | Why |
|-----------|-----|
| Raw SQL | Leaks full statement |
| Expression tree/body | Leaks schema logic |
| Exclusion columns | Leaks constraint shape |
| Exclusion operators | Leaks implementation detail |
| Operator classes | Leaks implementation detail |
| Predicate text | Leaks schema logic |
| Sequence options | Leaks configuration detail |
| Catalog state | Runtime dependency |
| Validation result | Runtime dependency |
| Dependency graph | Runtime dependency |
| Rewrite duration estimate | Runtime dependency |

## Public Contract / Non-Goals

DeltaScope will:
- Emit notice findings for FK deferrability changes (`DEFERRABLE`, `INITIALLY DEFERRED`).
- Keep metadata bounded and consistent across SDK, CLI, HTTP, MCP.
- Normalize `SET WITHOUT OIDS` silently (no finding).

DeltaScope will not:
- Claim full PostgreSQL ALTER TABLE support.
- Claim PostgreSQL 18 parser support.
- Validate live catalog state.
- Validate runtime FK behavior.
- Estimate rewrite or lock duration.
- Inspect or emit expressions, operators, or sequence options.

## Consequences

- After v0.160.0, `unsupported_boundary` drops from 7 to 4. The remaining 4 are all high-complexity or alternate-parser-path forms.
- `normalized_silent` reaches 2 (SET WITHOUT OIDS + the existing normalized silent case).
- The `constraint_type=foreign_key` metadata field is introduced for ALTER CONSTRAINT rules. Future constraint-type rules may use this field.
- PG18 parser errors (4) remain blocked until `pg_query_go v7` ships.
