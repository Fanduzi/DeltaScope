## Context

Official v0.510.0 run 33302045413 passed provenance then failed before any
assets. `TestAuditCommandLoadsTLSCAFile` dials empty loopback after a valid CA
parse. On Linux that returns typed `ECONNREFUSED`, which #57 already maps to
bounded `connection refused`. The test allowlist accepted only TLS hostname
or certificate, `connection failed`, or `connection timed out`.

## Decision

Keep the #57 production mapping. Extend only that test's bounded-runtime
allowlist to accept `connection refused`. Do not collapse refused into
`connection failed`, and do not add a helper or new category.

Treat v0.510.1 as the publish of already-reviewed #54–#57 plus this
deterministic test correction. Preserve v0.510.0 historical notes and tag
references. Do not advertise v0.510.0 as a successful published GitHub
Release, and do not add a v0.510.0 landing history card.

## Rationale

The failure was a Linux-empty-loopback test contract, not a product-message
regression. Production already emits the bounded refused line. Widening the
allowlist matches Darwin TLS/timeout and Linux refused without changing
portable output.

v0.510.0 produced no GitHub Release assets. A landing history card would
present it as a shipped milestone.

## Public Contract

- Metadata-aware CLI typed TCP refusal remains `connection refused`, exit 3.
- `TestAuditCommandLoadsTLSCAFile` accepts that bounded line after a valid CA
  parse, alongside the previous TLS / failed / timed-out lines.
- Portable CLI output still omits host, port, user, database, schema, DSN,
  password, raw driver text, filesystem path, and version.
- Current install pins, runtime/package versions, and landing current
  surfaces name v0.510.1. Landing recent cards stay v0.500.0, v0.490.0,
  v0.480.0.

## Deferred / Out Of Scope

- Production remapping of refused into `connection failed`.
- A v0.510.0 GitHub Release, retag, or landing history card.
- Changes to Query Access, HTTP, MCP, SDK, or successful metadata-aware
  audits.
- Rule catalog, corpus, or DDL coverage changes.
