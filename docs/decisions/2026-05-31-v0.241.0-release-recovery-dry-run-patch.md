## Context

v0.240.0 added `.github/workflows/release-recover.yml`, a manual `workflow_dispatch` workflow for recovering Homebrew and npm publishing after partial release failure. The workflow was statically verified (YAML parse, grep safety checks, GitNexus `detect_changes`) and the normal release path succeeded.

However, the recovery workflow itself was **not dispatched** because it had no safe dry-run mode. An operator wanting to validate that the recovery workflow works at runtime had only two choices:

1. Rely on static YAML/script checks. These prove syntax and structural correctness but cannot confirm runtime behavior (secret resolution, action version pinning, environment bootstrapping, checksum extraction).
2. Dispatch the workflow as-is, which may push to the Homebrew tap or publish npm.

Neither option is a sufficient confidence gate for release infrastructure.

## Decision

Add a `dry_run` boolean input to `.github/workflows/release-recover.yml`, defaulting to `true`.

Dry-run exercises all non-destructive recovery logic to prove the workflow can run end-to-end without mutating downstream state. Non-dry-run mode (`dry_run=false`) preserves the v0.240.0 real recovery behavior.

## Dry-Run Contract

When `dry_run=true`, the workflow **will**:

- Run preflight checks (release asset validation, checksum download/extraction).
- Render and verify Homebrew cask syntax/content.
- Clone the Homebrew tap.
- Copy the rendered cask into the tap checkout.
- Compute whether the cask would change (`git diff`).
- Check npm package state (`present` or `absent`).

When `dry_run=true`, the workflow **will not**:

- Push to the Homebrew tap (`git push`).
- Install the Homebrew cask (`brew install`).
- Publish to npm (`npm publish`).
- Upload or delete GitHub Release assets (`gh release upload/delete`).
- Create or delete tags.

## Non-Dry-Run Contract

When `dry_run=false`, the workflow preserves v0.240.0 behavior:

- Homebrew: commit and push cask only if diff exists; exit 0 if already up to date.
- npm: publish only if absent and `recover_npm=true`; skip if already present.
- Homebrew install verification: run only when `verify_homebrew=true` and `recover_homebrew=true`.

## Verification Plan

1. Static checks: `make decision-record-gate`, `git diff --check`.
2. Preflight helpers: `VERSION=v0.240.0 make release-recovery-preflight`.
3. Static grep confirming `git push`, `npm publish`, `brew install` are guarded behind `DRY_RUN=false` or `!inputs.dry_run`.
4. GitNexus `detect_changes` confirming no audit/parser/rule changes.
5. After release: manually dispatch `release-recover.yml` with `dry_run=true` against an existing release and verify workflow succeeds without Homebrew/npm mutation.

## Non-Goals

- No SQL audit behavior changes.
- No parser, rule, or policy changes.
- No changes to `release.yml` (full release workflow) behavior.
- No automatic trigger of recovery from the release workflow.
- No npm or Homebrew publishing during implementation tasks.
- No tag, release, or asset deletion or recreation.

- Homebrew publish step: clone/copy/diff always run; `git push` only when `DRY_RUN=false`.
- Homebrew install verify job: skipped when `dry_run=true` via `!inputs.dry_run` condition.
- npm publish step: state check always runs; `npm publish` only when absent + `DRY_RUN=false`.
- All destructive operations (`git push`, `npm publish`, `brew install`) gated behind `dry_run=false` or `!inputs.dry_run`.
- No audit/parser/rule changes; no runtime Go code changes.
