# Decision: PostgreSQL ordinary-table rename and schema destinations

Date: 2026-11-18
Status: Accepted
Milestone: F09 / `milestone/pg-alter-semantics` (D15)
Product baseline: `7ba14c4c9ed75444f269f15a25ad63942233a9a6`

## Decision

Enable `ddl.pg.alter.rename_table.target.valid` and
`ddl.pg.alter.set_schema.target.valid` as blockers without parameters. Both
require observed PostgreSQL 17 and a fresh, exact schema-qualified ordinary
persistent non-typed table. A proven qualified absent table with `IF EXISTS`
has no destination premise. Unknown, stale or misbound facts remain gaps.

RENAME checks the exact relation name in the current schema. Any existing
relation of that name, including the source itself, is an observed conflict.
The direct row-type name is also checked. A defined, truly autogenerated
array whose element points back to it can be renamed out of the way by
PostgreSQL. An unknown array relationship retains a gap. The independent
rename forbid retains its original behavior.

SET SCHEMA checks existence of the exact named destination schema, the
primary relation name and its row-type name. An observed same schema has
no move premise, and the existing notice states that no relocation occurs.
An observed missing schema, occupied primary relation name or occupied
row-type name blocks. The same-schema case does not reinterpret member
names as collisions. Dependent indexes, sequences, constraints and array
types moved by the backend remain distinct premises. No permissions,
execution or full relocation legality is claimed by this slice.

Observations remain private. Findings carry the action, source table
identity and bounded reason. The existing SET SCHEMA notice retains its
level and public shape, with conditional relocation language.

## Evidence

PostgreSQL 17.7 paired native/CLI research covered 14 statements and 28
audits at `3aaf1f50`, and 11 statements and 22 audits at `7ba14c4c`.
Exact relation name collisions return `42P07`, a direct nonmovable type
collision returns `42710`, and a missing destination schema returns `3F000`.
The edge probe verified the autogenerated array exception using native
catalog readback. It also showed that an owned index or sequence can block
SET SCHEMA independently of the direct table and row-type names. Catalog,
file, data and an unrelated sequence were verified around each audit and
native rollback. The later artifact is
`/tmp/ds-pg-f09-rename-schema-edges-7ba14c4c/evidence.json`.
