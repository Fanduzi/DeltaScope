## Context

After v0.120.0 shipped PostgreSQL semantic metadata and long-tail DDL enhancements, the existing ALTER TABLE coverage census (`postgresql_alter_table_coverage_census_postgresql_tag_test.go`) covers 42 baseline cases: 40 finding-covered, 1 normalized-silent, 1 unsupported-explicit.

PostgreSQL `ALTER TABLE` supports over 40 distinct action types. DeltaScope covers selected migration-safety patterns, not the full grammar. Without a durable characterization of the residual surface, future contributors or agents may incorrectly assume full ALTER TABLE support, or may waste effort on low-priority syntax families.

Task 1 created a residual census (66 cases across 7 families) to serve as the planning source for the next implementation pack.

## Decision

1. The Task 1 residual census is the authoritative planning source for the next batch of PostgreSQL ALTER TABLE implementation work.
2. DeltaScope does not claim full PostgreSQL ALTER TABLE grammar coverage. Public docs and release notes must not state "full PostgreSQL ALTER TABLE support."
3. Unsupported and parser-error forms are intentional boundaries until explicitly promoted through a future decision.
4. Future ALTER TABLE findings continue to follow bounded metadata / no-payload principles: no expression bodies, no operator payloads, no partition bound literals.

## Recommended Next Pack

1. **Priority 1: parser-error boundary documentation / parser support investigation** — PG17 syntax blocks downstream normalization and rule evaluation. Four forms cannot be classified until the parser handles them.
2. **Priority 2: table_properties family** — Largest unsupported family (12/12 unsupported). Includes storage, tuning, and layout actions (SET ACCESS METHOD, SET/RESET reloptions, INHERIT/NO INHERIT, CLUSTER, OF/NOT OF).
3. **Priority 3: trigger_rule_rls residuals** — Bounded identities with high operational risk. REPLICA/ALWAYS trigger modes and all rule variants are unsupported. RLS subset already partially covered.
4. **Priority 4: column_attributes** — Bounded metadata candidates (STATISTICS, n_distinct, STORAGE, COMPRESSION), but lower migration-safety priority and some generated-expression payload risk.
5. **Priority 5: constraint residuals** — EXCLUDE USING gist and ALTER CONSTRAINT DEFERRABLE have high value, but parser gaps and expression/operator payload risks require careful handling.

## Public Contract

- DeltaScope reports selected PostgreSQL ALTER TABLE migration-safety patterns with bounded metadata.
- Findings may be added for specific bounded actions in future milestones.
- Unsupported and parser-error forms are intentional boundaries until explicitly promoted.
- Public docs and release notes must not claim "full PostgreSQL ALTER TABLE support."

## Deferred / Out of Scope

- Generated expressions: do not emit expression bodies.
- CHECK/EXCLUDE expressions/operators: do not emit expression or operator payload.
- Partition bounds: do not emit bound expressions.
- Live catalog validation: not performed.
- Function/operator volatility or immutability: not inferred.
- Full PostgreSQL ALTER TABLE grammar support: not claimed.
- DCL/permission expansion: out of scope.

## Verification Evidence

- Residual census test: 66 cases, 0 unclassified, all families fully classified.
- Test passes under `go test -tags postgresql -run TestPostgreSQLAlterTableResidualCensus -v`.
- GitNexus detect_changes confirms test-only commit with 0 production symbols affected.

## Consequences

- Future ALTER TABLE implementation packs should reference this decision and the residual census for prioritization.
- When new ALTER TABLE actions are promoted from unsupported to finding-covered, the residual census test should be updated to reflect the new classification.
- Parser-error cases require upstream TiDB parser changes before DeltaScope can classify them; track these separately.
