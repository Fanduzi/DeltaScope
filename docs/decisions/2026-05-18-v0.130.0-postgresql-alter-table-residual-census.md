## Context

After v0.120.0 shipped PostgreSQL semantic metadata and long-tail DDL enhancements, the existing ALTER TABLE coverage census (`postgresql_alter_table_coverage_census_postgresql_tag_test.go`) covers 42 baseline cases: 41 finding-covered, 1 normalized-silent.

PostgreSQL `ALTER TABLE` supports over 40 distinct action types. DeltaScope covers selected migration-safety patterns, not the full grammar. Without a durable characterization of the residual surface, future contributors or agents may incorrectly assume full ALTER TABLE support, or may waste effort on low-priority syntax families.

Task 1 created a residual census (66 cases across 7 families) to serve as the planning source for the next implementation pack. Tasks 3A–3C implemented the first pack: storage/layout rules (`SET TABLESPACE`, `SET ACCESS METHOD`) and their public surface coverage.

## Decision

1. The Task 1 residual census is the authoritative planning source for the next batch of PostgreSQL ALTER TABLE implementation work.
2. DeltaScope does not claim full PostgreSQL ALTER TABLE grammar coverage. Public docs and release notes must not state "full PostgreSQL ALTER TABLE support."
3. Unsupported and parser-error forms are intentional boundaries until explicitly promoted through a future decision.
4. Future ALTER TABLE findings continue to follow bounded metadata / no-payload principles: no expression bodies, no operator payloads, no partition bound literals.
5. This decision record has been expanded from "residual census prioritization" to include the storage/layout implementation results (Tasks 3A–3C).

## Promoted Rules

Three cases were promoted from `unsupported_boundary` to `finding_covered` by the storage/layout rules:

### `ddl.pg.alter.set_tablespace.notice`

| Field | Value |
|-------|-------|
| Level | notice |
| SQL family | `ALTER TABLE ... SET TABLESPACE ...` |
| Metadata | `operation=alter_table`, `action=set_tablespace`, `table`, `tablespace` |

### `ddl.pg.alter.set_access_method.warn`

| Field | Value |
|-------|-------|
| Level | warning |
| SQL family | `ALTER TABLE ... SET ACCESS METHOD ...` / `SET ACCESS METHOD DEFAULT` |
| Metadata | `operation=alter_table`, `action=set_access_method`, `table`, `access_method`, `is_default` |

Notes:
- `is_default` is a string `"true"` / `"false"` because rule options maps use `map[string]string`.
- `SET ACCESS METHOD DEFAULT` sets `access_method` to `"default"` and `is_default` to `"true"`.

### Pre-existing Coverage

`SET LOGGED` and `SET UNLOGGED` are covered by pre-existing rules and were not promoted in this pack:
- `ddl.pg.alter.set_logged.notice`
- `ddl.pg.alter.set_unlogged.notice`

## Public Surface Coverage

SDK, CLI, HTTP, and MCP all assert:
- `set_tablespace` rule fires with correct metadata (`action`, `tablespace`, `table`).
- `set_access_method` rule fires for both heap and DEFAULT variants.
- `is_default` metadata parity across all surfaces.
- Corpus: `509/509` supported targets covered, coverage `100%`.

## No-Leak / No-Overclaim

The storage/layout rules do not output:
- `fillfactor`, `reloptions`, `cluster`, `tablespace_sql`, `access_method_sql`
- They do not claim to validate whether the target tablespace or access method exists.
- They do not claim to estimate rewrite duration or perform live validation.

## Parser Error List

| Case | SQL | Reason |
|------|-----|--------|
| NOT NULL NOT VALID | `ALTER TABLE users ADD CONSTRAINT users_email_nn NOT NULL email NOT VALID` | PG17 NOT NULL constraint syntax not parsed by TiDB parser |
| ALTER CONSTRAINT NOT ENFORCED | `ALTER TABLE orders ALTER CONSTRAINT orders_user_id_fkey NOT ENFORCED` | PG17 NOT ENFORCED not parsed |
| ALTER CONSTRAINT INHERIT | `ALTER TABLE users ALTER CONSTRAINT users_email_nn INHERIT` | syntax error near INHERIT |
| ALTER CONSTRAINT NO INHERIT | `ALTER TABLE users ALTER CONSTRAINT users_email_nn NO INHERIT` | parser rejects NO INHERIT on FK |

## Deferred / Out of Scope

- reloptions `SET (...)` / `RESET (...)`
- `CLUSTER ON` / `SET WITHOUT CLUSTER`
- `SET WITHOUT OIDS`
- `INHERIT` / `NO INHERIT`
- `OF TYPE` / `NOT OF`
- `ALTER TABLE ALL IN TABLESPACE`
- PG17 parser-error syntax (NOT NULL NOT VALID, ALTER CONSTRAINT NOT ENFORCED/INHERIT/NO INHERIT)
- CHECK/EXCLUDE expressions: do not emit expression bodies.
- Generated expressions: do not emit expression bodies.
- Partition bounds: do not emit bound expressions.
- Live catalog validation of tablespace/access method existence: not performed.
- Function/operator volatility or immutability: not inferred.
- Full PostgreSQL ALTER TABLE grammar support: not claimed.
- DCL/permission expansion: out of scope.

This milestone is not "full PostgreSQL ALTER TABLE support."

## Recommended Next Pack

1. **Priority 1: parser-error boundary documentation / parser support investigation** — PG17 syntax blocks downstream normalization and rule evaluation. Four forms cannot be classified until the parser handles them.
2. **Priority 2: remaining table_properties family** — 10/12 still unsupported. Includes `SET (...)` / `RESET (...)` reloptions, `CLUSTER ON` / `SET WITHOUT CLUSTER`, `SET WITHOUT OIDS`, `INHERIT` / `NO INHERIT`, `OF TYPE` / `NOT OF`, `ALTER TABLE ALL IN TABLESPACE`.
3. **Priority 3: trigger_rule_rls residuals** — Bounded identities with high operational risk. REPLICA/ALWAYS trigger modes and all rule variants are unsupported. RLS subset already partially covered.
4. **Priority 4: column_attributes** — Bounded metadata candidates (STATISTICS, n_distinct, STORAGE, COMPRESSION), but lower migration-safety priority and some generated-expression payload risk.
5. **Priority 5: constraint residuals** — EXCLUDE USING gist and ALTER CONSTRAINT DEFERRABLE have high value, but parser gaps and expression/operator payload risks require careful handling.

## Public Contract

- DeltaScope reports selected PostgreSQL ALTER TABLE migration-safety patterns with bounded metadata.
- `ddl.pg.alter.set_tablespace.notice` fires on `ALTER TABLE ... SET TABLESPACE ...` with `tablespace` metadata.
- `ddl.pg.alter.set_access_method.warn` fires on `ALTER TABLE ... SET ACCESS METHOD ...` with `access_method` and `is_default` metadata.
- Findings may be added for specific bounded actions in future milestones.
- Unsupported and parser-error forms are intentional boundaries until explicitly promoted.
- Public docs and release notes must not claim "full PostgreSQL ALTER TABLE support."

## Verification Evidence

- Residual census test: 66 cases, 0 unclassified, all families fully classified.
- Baseline coverage census: 42 cases, 41 finding-covered, 1 normalized-silent.
- Census shift verified: `finding_covered` 29→32, `unsupported_boundary` 32→29.
- Corpus: 509/509 supported targets covered, 100% coverage.
- Public surface tests pass across SDK, CLI, HTTP, MCP for set_tablespace and set_access_method (including DEFAULT variant).
- All tests pass under `go test -tags postgresql`.

## Consequences

- Future ALTER TABLE implementation packs should reference this decision and the residual census for prioritization.
- When new ALTER TABLE actions are promoted from unsupported to finding-covered, the residual census test should be updated to reflect the new classification.
- Parser-error cases require upstream TiDB parser changes before DeltaScope can classify them; track these separately.
