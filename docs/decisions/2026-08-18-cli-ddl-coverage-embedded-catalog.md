## Context

`deltascope ddl-coverage` is documented as a shipped catalog lookup. Release
binaries resolved `docs/reference/ddl-coverage-catalog.json` from the current
working directory. From an empty directory the command failed with exit `3`
and `open docs/reference/ddl-coverage-catalog.json: no such file or directory`.
The v0.480.0 tarball does not include that JSON. The v0.280.0 decision already
described an embedded/generated catalog; the shipped command never embedded it.

## Decision

Compile the generated catalog into the binary. `ddl-coverage` loads that
embedded copy by default.

- Source of truth remains the census-generated catalog. The generator writes
  `docs/reference/ddl-coverage-catalog.json` and
  `internal/application/audit/catalogdata/ddl-coverage-catalog.json`.
- The application loader embeds the `catalogdata` copy. It is not a
  hand-maintained list.
- Hidden `--catalog` remains a path override for tests and local experiments.
  A missing or unreadable override exits `2` with a `catalog unavailable`
  message. That is a user/environment problem, not an internal failure.
- A corrupt embedded catalog is a packaging bug and stays exit `3`.

## Rationale

Embedding is the smallest install-independent fix that matches the published
help text. A well-known install path would still fail for tarball, Homebrew,
and `install.sh` users unless every packager copied the JSON. Dropping the
command from release builds would shrink the advertised CLI.

Two generated files are required because `//go:embed` cannot traverse `..`.
The drift gate compares both copies to the same generated bytes.

## Public Contract

- `deltascope ddl-coverage --limit 5` from an empty directory exits `0` on a
  published-style binary and prints generated catalog rows.
- Filter flags, text/JSON output, and empty-result success are unchanged.
- Missing `--catalog` path: stderr contains `catalog unavailable`, exit `2`.
- Audit evaluation, SDK, HTTP, and MCP are unchanged.

## Deferred / Out Of Scope

- SDK, HTTP, or MCP catalog query
- Changing audit evaluation
- Claiming vendor grammar completeness
- Shipping the JSON as a separate install file
- Making `--catalog` a documented user flag

## Verification Evidence

CLI `Execute` tests cover an empty working directory, existing filters against
the embedded catalog, and a missing override path. Application tests require
the embedded entries to match the checked-in generated JSON (400 entries,
version `v0.270.0`).

## Consequences

Catalog regeneration must write both JSON paths. Do not replace the embed
copy with a hand-edited subset. Future catalog-query surfaces should reuse
`LoadEmbeddedCatalog` rather than a cwd-relative path.
