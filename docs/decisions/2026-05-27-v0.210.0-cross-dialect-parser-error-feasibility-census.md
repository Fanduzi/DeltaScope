# Decision: Cross-Dialect Parser-Error Feasibility Census

Date: 2026-05-27
Status: Accepted
Related milestone/version: v0.210.0
Related tests:
  `internal/application/audit/ddl_parser_error_feasibility_census_test.go`
  `internal/application/audit/ddl_parser_error_feasibility_census_postgresql_tag_test.go`

## Context

v0.200.0 cleared all tracked parseable MySQL/TiDB DDL gaps by promoting 25+27 `normalized_silent` forms to `finding_covered`. The remaining high-level gap class across all three dialects is `parser_error` — forms that the parser library cannot parse at all.

v0.200.0 census baseline:

| Dialect | Total | Finding Covered | Normalized Silent | Unsupported Boundary | Parser Error |
|---|---:|---:|---:|---:|---:|
| MySQL | 61 | 46 | 0 | 0 | 15 |
| TiDB | 54 | 45 | 0 | 0 | 9 |
| PostgreSQL | 285 | 274 | 6 | 0 | 5 |

## Decision

v0.210.0 classifies every remaining tracked DDL `parser_error` form into exactly one feasibility bucket. No parser behavior changes, no new rules, no fallback extraction.

### Feasibility Buckets

| Bucket | Meaning |
|---|---|
| `parser_upgrade_candidate` | Likely supported by newer parser/library versions; do not fallback yet |
| `bounded_fallback_candidate` | Could be safely detected with a small bounded pre-parser fallback; no payload leak |
| `product_unsupported_or_inapplicable` | Dialect product does not support the feature or support is intentionally out of scope |
| `unsafe_fallback_defer` | Fallback would require parsing bodies, predicates, option payloads, or sensitive strings |
| `needs_research` | Evidence insufficient; must not be promoted |

### Next Actions

| Bucket | Next Action |
|---|---|
| `parser_upgrade_candidate` | Monitor TiDB parser and pg_query_go releases; re-test after upgrade |
| `bounded_fallback_candidate` | Design bounded pre-parser fallback for object identity extraction in a future milestone |
| `product_unsupported_or_inapplicable` | No action; these forms are intentionally out of scope for the dialect |
| `unsafe_fallback_defer` | Defer until parser upgrade path is exhausted; do not attempt regex/string fallback |
| `needs_research` | Gather more evidence before classifying |

## Non-Goals

- Do not add audit rules.
- Do not change parser behavior.
- Do not add fallback extraction in this milestone.
- Do not update release surfaces until the release-surface phase.
- Do not claim parser-error forms are supported.
- Do not claim full DDL support or dialect parity.
- Do not expose raw SQL, routine bodies, trigger bodies, event bodies, passwords, catalog state, runtime validation, lock duration, or rewrite duration.
