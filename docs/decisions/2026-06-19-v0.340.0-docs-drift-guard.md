## Context

Recent releases fixed several user-facing documentation drift issues after implementation had already landed:

- stale `deltascope rules show` and `deltascope rules search` examples,
- incomplete audit output-format lists,
- outdated GitHub Actions workflow examples,
- version pins that could point at a release that does not support the documented format,
- wording that blurred DeltaScope's public `level` field with external `severity` fields.

The repository already has release gates for version surfaces, release facts, source-location fidelity, CI renderer smoke tests, and package/archive checks. Those gates do not directly protect current public docs and examples from drifting away from supported CLI contracts.

## Decision

Add a release-blocking docs drift guard for current public docs and examples. The guard will be static and curated: it checks known high-risk public contracts rather than executing arbitrary snippets from documentation.

The first supported scope is:

- `README.md`
- `README_ZH.md`
- `docs/reference/cli.md`
- `docs/reference/cli.zh-CN.md`
- `docs/reference/config.md`
- `docs/reference/config.zh-CN.md`
- `docs/recipe/*.md`
- `docs/recipe/*.zh-CN.md`
- `docs/examples/github-actions.yml`
- `docs/examples/gitlab-ci.yml`
- `docs/examples/runtime-config.yaml`

The guard will check:

- stale rule-inspection commands such as `deltascope rules show` and `deltascope rules search`,
- audit output-format inventory where current docs list supported formats,
- GitHub Actions example shape, including read-only permissions, no PR-comment bot behavior, no token handling, `config lint --strict`, `github-actions` annotations, and `github-summary` job summary output,
- release-version pin consistency in the GitHub Actions example when `VERSION=vX.Y.Z` is supplied,
- misuse of `severity field` language for DeltaScope's public priority, while allowing external schema contexts and negative clarification such as "no `severity` field".

The guard will run from a new release-oriented target, planned as `make docs-example-gates VERSION=vX.Y.Z`, and will be wired into `release-surface-gates`.

## Rationale

The drift patterns are repeated, high-confidence, and costly when discovered late. A small static checker is enough to catch the common failures without turning documentation into executable test fixtures.

The guard belongs in release-surface gates, not the fast local `make test` path. These are release-facing public-doc checks; they should block a release when stale, but they should not slow normal development loops.

Static curated checks are safer than executing every fenced shell block:

- docs often contain examples that require local paths or CI environment variables,
- workflow examples may mention remote installers,
- arbitrary snippet execution risks network access, token assumptions, or destructive commands,
- the goal is drift detection, not complete documentation truth verification.

## Public Contract

The new repository contract is:

- `make docs-example-gates VERSION=vX.Y.Z` validates current public docs and examples against the curated drift rules.
- `release-surface-gates` includes that docs-example gate.
- Failures include file path, line number when available, and a remediation hint.
- The checker does not require network, Docker, databases, GitHub API access, npm, Homebrew, or secrets.
- The checker does not execute arbitrary Markdown or YAML snippets.

This is a repository release contract, not a new user-facing DeltaScope CLI feature.

## Deferred / Out Of Scope

- No validation of historical release notes, changelog entries, or decision records. Those files may contain old commands as historical context.
- No execution of arbitrary documentation code blocks.
- No full Markdown linting.
- No full prose truth checker.
- No validation of every README claim.
- No GitHub API, npm, Homebrew, Docker, or database calls.
- No new public CLI command.
- No audit behavior, parser behavior, rule behavior, default-policy, finding JSON, SDK, HTTP, MCP, SARIF, GitHub Actions, or GitLab Code Quality output-shape change.
- No cleanup or promotion of local scratch tools such as `cmd/catalog_stats/`.
- No landing-page content guard in the first version. The landing page remains covered by `make lint-landing` and existing release version-surface gates.

## Consequences

Future public docs changes that touch commands, CI examples, or output-format lists must keep the docs drift guard green. When a new audit output format or command name is added, the guard's curated allow-list must be updated in the same milestone.

Historical docs remain historical. The guard should not be broadened into `docs/releases/`, `CHANGELOG.md`, or `docs/decisions/` without a separate decision because those areas preserve old release context.

Current repo check (`VERSION=v0.330.0 python3 scripts/verify_docs_examples.py`)
is RED on one real, pre-existing public-doc drift finding, deferred to Task 4
(docs cleanup) per the milestone task boundaries:

    docs-examples: FAIL
    docs/examples/gitlab-ci.yml:0: GitLab CI example missing required
      `gitlab-codequality` output format

`gitlab-codequality` is a supported format
(`internal/interfaces/cli/root.go`, `internal/infrastructure/output/gitlabcodequality`),
but `docs/examples/gitlab-ci.yml` predates it and only emits `--format json`
to artifacts. Every other check passes against the current repo. The checker
was kept strict on purpose; the allow-list was not broadened to mask this
drift. The release gate is therefore expected to stay red until Task 4 fixes
`gitlab-ci.yml`.

Implementation clarifications:

- `severity field` is matched per line; a finding is suppressed when the same
  line matches a negative clarification (`no severity field`,
  `not add a severity field`) or an external-schema context
  (`GitLab Code Quality`, `external severity`, `fail-on severity`). Line-level
  scoping keeps the check conservative rather than a broad prose linter.
- `main()` resolves the repo root from the script location (`scripts/../`) by
  default and accepts an optional root argument so the test suite can point it
  at temporary repos.
- File-level findings (a missing format or a missing required example token)
  render with line `0`.
