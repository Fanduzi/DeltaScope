## Context

v0.140.0 left 11 `unsupported_boundary` and 4 `parser_error` in the PostgreSQL ALTER TABLE residual census (66 total cases across 7 families). The `table_properties` family has 4 remaining unsupported cases, all table relationship forms: INHERIT, NO INHERIT, OF, and NOT OF.

v0.150.0 focuses only on these 4 table relationship forms. An AST census was performed to verify parser feasibility before any production code is written.

### Parser Dependency

Current parser: `github.com/pganalyze/pg_query_go/v6 v6.2.2`, backed by libpg_query 17. PG18 parser-error forms remain out of scope.

## AST Census Results

All 4 candidates parse successfully and produce stable `AlterTableStmt` nodes with distinguishable subtypes.

| # | SQL | Subtype | Val | CmdName | HasDef | DefKind | Identity Source |
|---|-----|---------|-----|---------|--------|---------|-----------------|
| 1 | `ALTER TABLE child_users INHERIT users` | `AT_AddInherit` | 51 | (empty) | true | `RangeVar` | parent table via def.RangeVar.relname |
| 2 | `ALTER TABLE child_users NO INHERIT users` | `AT_DropInherit` | 52 | (empty) | true | `RangeVar` | parent table via def.RangeVar.relname |
| 3 | `ALTER TABLE users OF user_type` | `AT_AddOf` | 53 | (empty) | true | `TypeName` | type name via def.TypeName.names |
| 4 | `ALTER TABLE users NOT OF` | `AT_DropOf` | 54 | (empty) | false | - | table only, no payload |

### Key AST Discoveries

1. **INHERIT / NO INHERIT**: The parent table is NOT in `cmd.GetName()` (empty string). Instead, it is in `def.RangeVar.relname`. The RangeVar also carries `inh=true` and `relpersistence="p"`, which are not identity fields. The parent table name is stable and directly extractable.

2. **OF type_name**: The type name is NOT in `cmd.GetName()` (empty string). Instead, it is in `def.TypeName.names` as a list of String nodes (`[{sval:"user_type"}]`). The type name is stable and directly extractable by joining names with ".".

3. **NOT OF**: `hasDef=false`, no def node. Pure table-only action with no payload. Distinguished from OF by absence of def.

4. **CmdName is empty for all 4 forms**: Unlike column-oriented subtypes (SET STATISTICS, SET STORAGE) where `cmd.GetName()` carries the column name, relationship subtypes use `cmdName=""` and carry identity in the def node or nowhere (NOT OF).

## Decision

### Promote / Defer Table

All 4 candidates are promoted to `finding_covered`. All have stable identity fields with no inseparable payload.

| # | Candidate | Decision | Rationale |
|---|-----------|----------|-----------|
| 1 | INHERIT | **promote** | Stable subtype AT_AddInherit, parent table in def.RangeVar.relname |
| 2 | NO INHERIT | **promote** | Stable subtype AT_DropInherit, parent table in def.RangeVar.relname |
| 3 | OF type | **promote** | Stable subtype AT_AddOf, type name in def.TypeName.names |
| 4 | NOT OF | **promote** | Stable subtype AT_DropOf, table-only with no payload |

### Proposed Rule IDs

| Rule ID | Level | SQL Family | Covers |
|---------|-------|------------|--------|
| `ddl.pg.alter.add_inherit.notice` | notice | `INHERIT parent_table` | Table inheritance addition |
| `ddl.pg.alter.drop_inherit.notice` | notice | `NO INHERIT parent_table` | Table inheritance removal |
| `ddl.pg.alter.add_of_type.notice` | notice | `OF type_name` | Typed table creation |
| `ddl.pg.alter.drop_of_type.notice` | notice | `NOT OF` | Typed table removal |

### Forbidden Payload

The following must NEVER appear in finding metadata:

| Forbidden | Why |
|-----------|-----|
| Raw SQL | Leaks full statement |
| Column definitions inherited from parent | Leaks schema shape |
| Typed table column shape | Leaks schema shape |
| Type attributes | Leaks configuration detail |
| Catalog state | Runtime dependency |
| Compatibility validation result | Runtime dependency |
| Rewrite duration estimate | Runtime dependency |
| Parent/type existence validation | Runtime dependency |

## Explicit Out of Scope

- `SET WITHOUT OIDS` (obsolete in PG12+, no practical audit value)
- `ALTER TABLE ALL IN TABLESPACE` (DDL routing, not structural)
- `SET EXPRESSION` (expression body risk)
- `ADD GENERATED ... AS IDENTITY` (identity body risk)
- `EXCLUDE USING gist` (operator payload)
- `ALTER CONSTRAINT DEFERRABLE`
- `ALTER CONSTRAINT INITIALLY DEFERRED`
- PG18 parser-error forms (4 cases)
- Live catalog validation
- Runtime behavior validation
- Rewrite duration estimate
- Parser upgrade

## Public Contract / Non-Goals

- No full PostgreSQL ALTER TABLE support claim. Public docs and release notes must not state "full PostgreSQL ALTER TABLE support."
- Findings are informational (all at notice level) — none indicate data loss risk.
- `parent_table` emits the parent table name only, not the inherited column definitions or constraint metadata.
- `type` emits the composite type name only, not the type's internal structure.
- No live validation of parent/type existence or compatibility.
- No PostgreSQL 18 parser support.

## Verification Evidence

- AST census test: 4 cases, 0 parse failures, all subtypes confirmed stable (AT_AddInherit=51, AT_DropInherit=52, AT_AddOf=53, AT_DropOf=54).
- Stable shape assertions: all 4 candidates produce AlterTableStmt with expected subtype values.
- Def payload detail: INHERIT/NO INHERIT confirmed RangeVar with parent in relname; OF confirmed TypeName with name in names list; NOT OF confirmed no def.
- Identity field mapping: all 4 candidates have extractable identity fields with no inseparable payload.

## Consequences

- After v0.150.0, `table_properties` family reaches 10/12 finding_covered (2 unsupported: SET WITHOUT OIDS, ALL IN TABLESPACE).
- 7 `unsupported_boundary` remain across `column_attributes` (3) and other families (4).
- The `relationship` metadata field (`inheritance`, `typed_table`) is introduced as a new classification dimension. Future relationship-type rules (foreign key, partition) may use this field if appropriate.
- INHERIT/NO INHERIT use `def.RangeVar.relname` for parent identity, following the same RangeVar pattern as DETACH PARTITION (which uses `def.PartitionCmd.name.relname`). Extractors should handle both RangeVar variants.
