## Context

v0.130.0 left 21 `unsupported_boundary` and 4 `parser_error` in the PostgreSQL ALTER TABLE residual census (66 total cases across 7 families). The `column_attributes` family has 9 unsupported cases and the `table_properties` family has 8 remaining unsupported cases after reloptions were promoted in v0.130.0 Task 5.

v0.140.0 focuses only on bounded residuals: forms where the AST provides stable identity fields (column name, index name, partition name) without requiring expression bodies, operator payloads, or partition bounds. An AST census was performed on 10 candidates to verify parser feasibility before any production code is written.

### Parser Dependency

Current parser: `github.com/pganalyze/pg_query_go/v6 v6.2.2`, backed by libpg_query 17. PG18 parser-error forms remain out of scope.

## AST Census Results

All 10 candidates parse successfully and produce stable `AlterTableStmt` nodes with distinguishable subtypes.

### Key AST Discoveries

1. **SET STATISTICS DEFAULT** has `hasDef=false` (no def node). Distinguished from value form by absence of def. The value form carries `Integer(100)` in def — the numeric value must NOT be emitted.

2. **SET STORAGE DEFAULT** carries `String_("default")` in def. Distinguished from specific storage (`"external"`, `"extended"`, `"main"`, `"plain"`) by the string value.

3. **DETACH PARTITION FINALIZE** uses a separate subtype `AT_DetachPartitionFinalize` (val=63), distinct from plain `AT_DetachPartition` (val=62). The partition name is NOT in `cmd.GetName()` but in `def.PartitionCmd.name.relname`. Both FINALIZE and plain DETACH share the same PartitionCmd def structure; FINALIZE has `concurrent=false`.

4. **DETACH PARTITION CONCURRENTLY** (not a v0.140.0 candidate, but observed during census) uses `AT_DetachPartition` (same subtype as plain DETACH) with `PartitionCmd.concurrent=true`. Distinguished from plain DETACH by the concurrent flag. This form is deferred but the census documents it for future reference.

## Decision

### Promote / Defer Table

All 10 candidates are promoted to `finding_covered`. None require inseparable payload.

| # | Candidate | Decision | Rationale |
|---|-----------|----------|-----------|
| 1 | SET STATISTICS (value) | **promote** | Stable subtype, column in cmdName, value in def.Integer but ignored |
| 2 | SET STATISTICS (DEFAULT) | **promote** | Same subtype, column in cmdName, no def (distinguished by hasDef=false) |
| 3 | SET (column options) | **promote** | Stable subtype, column in cmdName, option count derivable from def.List |
| 4 | RESET (column options) | **promote** | Stable subtype, column in cmdName, reset count derivable from def.List |
| 5 | SET STORAGE (specific) | **promote** | Stable subtype, column in cmdName, storage value is bounded enum |
| 6 | SET STORAGE (DEFAULT) | **promote** | Same subtype, column in cmdName, def.String="default" distinguishes |
| 7 | SET COMPRESSION | **promote** | Stable subtype, column in cmdName, compression value is bounded |
| 8 | CLUSTER ON | **promote** | Stable subtype, index in cmdName, no def |
| 9 | SET WITHOUT CLUSTER | **promote** | Stable subtype, no identity beyond table, no def |
| 10 | DETACH PARTITION FINALIZE | **promote** | Separate subtype, partition in def.PartitionCmd, no bound payload |

### Proposed Rule IDs

| Rule ID | Level | SQL Family | Covers |
|---------|-------|------------|--------|
| `ddl.pg.alter.set_column_statistics.notice` | notice | `ALTER COLUMN ... SET STATISTICS` | Both value and DEFAULT variants |
| `ddl.pg.alter.set_column_options.notice` | notice | `ALTER COLUMN ... SET (...)` | Column-level reloptions SET |
| `ddl.pg.alter.reset_column_options.notice` | notice | `ALTER COLUMN ... RESET (...)` | Column-level reloptions RESET |
| `ddl.pg.alter.set_column_storage.notice` | notice | `ALTER COLUMN ... SET STORAGE` | Both specific and DEFAULT variants |
| `ddl.pg.alter.set_column_compression.notice` | notice | `ALTER COLUMN ... SET COMPRESSION` | Compression method |
| `ddl.pg.alter.cluster_on.notice` | notice | `CLUSTER ON index` | Cluster index assignment |
| `ddl.pg.alter.set_without_cluster.notice` | notice | `SET WITHOUT CLUSTER` | Cluster removal |
| `ddl.pg.alter.detach_partition_finalize.notice` | notice | `DETACH PARTITION ... FINALIZE` | Partition finalization |

Note: Cases 1+2 share rule `set_column_statistics`. Cases 5+6 share rule `set_column_storage`. This matches the v0.130.0 precedent where `SET ACCESS METHOD DEFAULT` shares a rule with `SET ACCESS METHOD heap`.

### Forbidden Payload

The following must NEVER appear in finding metadata:

| Forbidden | Why |
|-----------|-----|
| Raw SQL | Leaks full statement |
| Expression bodies | Leaks procedural logic |
| Generated expressions | Leaks computed values |
| Option names (e.g., `n_distinct`) | Leaks configuration detail |
| Option values (e.g., `-1`) | Leaks configuration values |
| Statistics numeric values (e.g., `100`) | Leaks tuning parameters |
| Compression method values (e.g., `lz4`) | Leaks implementation choice |
| Partition bounds | Leaks partition expressions |
| Live catalog state | Runtime dependency |
| Validation result | Runtime dependency |
| Rewrite duration estimate | Runtime dependency |

Exception: `storage_kind` values (`external`, `extended`, `main`, `plain`, `default`) are emitted because they are a bounded PostgreSQL enum that describes the storage strategy, not user configuration. This is parallel to the v0.130.0 precedent where `access_method` emits the method name (`heap`) as bounded metadata.

## Explicit Out of Scope

- `SET EXPRESSION` (expression body risk)
- `ADD GENERATED ... AS IDENTITY` (identity body risk)
- `DROP IDENTITY` (deferred)
- `EXCLUDE USING gist` (operator payload)
- `ALTER CONSTRAINT DEFERRABLE`
- `ALTER CONSTRAINT INITIALLY DEFERRED`
- `SET WITHOUT OIDS`
- `INHERIT` / `NO INHERIT`
- `OF type` / `NOT OF`
- `ALTER TABLE ALL IN TABLESPACE`
- `DETACH PARTITION ... CONCURRENTLY` (observed during census but not a candidate; uses `AT_DetachPartition` with `concurrent=true`; could be promoted in a future pack)
- PG18 parser-error forms (4 cases)
- Live catalog validation
- Runtime behavior validation
- Rewrite duration estimate
- Parser upgrade

## Public Contract / Non-Goals

- No full PostgreSQL ALTER TABLE support claim. Public docs and release notes must not state "full PostgreSQL ALTER TABLE support."
- Findings are informational (all at notice level) — none indicate data loss risk.
- `storage_kind` is emitted as bounded metadata because it comes from a fixed PostgreSQL enum. This does not set a precedent for emitting arbitrary string values.
- `has_compression` is a boolean flag; the compression method name is intentionally NOT emitted.
- Column option names and values are intentionally NOT emitted — only counts.
- Statistics target values are intentionally NOT emitted — only `value` vs `default` kind.

## Verification Evidence

- AST census test: 10 cases, 0 parse failures, all subtypes confirmed stable.
- Identity field mapping test: all 10 candidates have extractable identity fields (column/index/partition name).
- DETACH PARTITION flag test: 3 variants (plain, FINALIZE, CONCURRENTLY) confirmed with correct subtype and flag distinctions.
- Column statistics detail test: value vs DEFAULT distinguished by hasDef presence.
- Column options detail test: SET and RESET confirmed with List payload, item counts verified.
- Storage/compression detail test: specific and DEFAULT variants confirmed with String_ payload.
- Cluster detail test: CLUSTER ON and SET WITHOUT CLUSTER confirmed with correct subtype, name, and hasDef.

## Consequences

- Future ALTER TABLE implementation packs should reference this decision and the v0.130.0 residual census for remaining candidates.
- `DETACH PARTITION ... CONCURRENTLY` is now characterized in the AST census test and can be promoted in a future pack using the `concurrent` flag on `PartitionCmd`.
- The `storage_kind` emission sets a narrow precedent: only bounded PostgreSQL enums (`{plain, external, extended, main, default}`) qualify. Arbitrary string values from def nodes do not qualify.
- After v0.140.0, `column_attributes` has 3 remaining unsupported and `table_properties` has 4 remaining unsupported — both families are approaching full coverage.
