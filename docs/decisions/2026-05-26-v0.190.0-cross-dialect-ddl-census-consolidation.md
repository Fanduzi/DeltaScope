# DR: Cross-Dialect DDL Coverage Census Consolidation

Date: 2026-05-26
Milestone: v0.190.0
Status: Finalized

## Context

DeltaScope started as a MySQL/TiDB tool and later added PostgreSQL. After multiple PostgreSQL DDL milestones, PostgreSQL now has deeper coverage evidence than MySQL/TiDB:

| Dialect | Census surface |
|---|---|
| PostgreSQL | 5 focused census tests: representative, completion, deep coverage, long-tail, ALTER TABLE residual |
| MySQL | 18 representative DDL forms in cross-dialect census |
| TiDB | 18 representative DDL forms in cross-dialect census |

The project cannot currently answer this question with confidence:

> Across the MySQL/TiDB DDL surface that DeltaScope intends to track, which forms are finding-covered, silently normalized, explicitly unsupported, or parser-blocked?

## Decision

Establish a consolidated DDL coverage census layer that summarizes tracked DDL coverage by dialect and by source. Add reusable summary helpers (`ddlCensusSummary`, `summarizeDDLCensusResults`, `assertArithmetic`) so that future census tests produce machine-verifiable arithmetic without hand-counting.

This milestone does not add or change audit rules or parser behavior.

## Classification Contract

Every tracked DDL form must be classified into exactly one bucket:

| Classification | Meaning |
|---|---|
| `finding_covered` | Parser/extractor/audit pipeline emits at least one finding |
| `normalized_silent` | Parser/extractor normalizes the form but no rule fires |
| `unsupported_boundary` | Parser succeeds but extractor marks the statement unsupported |
| `parser_error` | Parser or extraction fails before a supported statement can be normalized |
| `unclassified` | Test bug; should remain zero |

Arithmetic invariant: `finding_covered + normalized_silent + unsupported_boundary + parser_error + unclassified == total`

## MySQL/TiDB Expansion Plan

Task 2 expanded MySQL and TiDB census coverage from 18 to 61/54 tracked forms covering 10 DDL families each.

### MySQL Final Census

| Dialect | Total | Finding Covered | Normalized Silent | Unsupported Boundary | Parser Error |
|---|---:|---:|---:|---:|---:|
| MySQL | 61 | 21 | 25 | 0 | 15 |

**MySQL parser_error (15):** ALTER VIEW, ALTER PROCEDURE, CREATE FUNCTION, ALTER FUNCTION, DROP FUNCTION, CREATE TRIGGER, DROP TRIGGER, CREATE EVENT, ALTER EVENT, DROP EVENT, CREATE TABLESPACE, ALTER TABLESPACE, DROP TABLESPACE, CREATE RESOURCE GROUP, ALTER RESOURCE GROUP.

### TiDB Final Census

| Dialect | Total | Finding Covered | Normalized Silent | Unsupported Boundary | Parser Error |
|---|---:|---:|---:|---:|---:|
| TiDB | 54 | 18 | 27 | 0 | 9 |

**TiDB parser_error (9):** ALTER VIEW, CREATE TRIGGER, DROP TRIGGER, CREATE FUNCTION, DROP FUNCTION, CREATE EVENT, DROP EVENT, ALTER TABLE TTL, ALTER TABLE LOCALITY.

**TiDB normalized_silent future-rule candidates:** RENAME TABLE, ALTER TABLE ADD/DROP/MODIFY COLUMN, ADD/DROP INDEX, ADD/DROP FOREIGN KEY, ADD PRIMARY KEY, standalone CREATE INDEX/UNIQUE INDEX, DROP INDEX, ALTER DATABASE, CREATE/DROP PROCEDURE, CREATE/ALTER/DROP PLACEMENT POLICY, CREATE/ALTER/DROP SEQUENCE, ALTER TABLE PLACEMENT POLICY, CREATE/ALTER/DROP USER, GRANT, REVOKE.

### Top MySQL Gaps

- **Parser gaps (15 forms):** The TiDB parser does not support triggers, events, functions, ALTER VIEW, ALTER PROCEDURE, tablespace, or resource groups (except DROP RESOURCE GROUP which parses successfully). These require parser-level work before rule coverage is possible.
- **Normalized silent candidates:** RENAME TABLE, standalone CREATE INDEX, ALTER DATABASE, and privilege/DCL statements parse and normalize but emit no findings.
- **No unsupported_boundary:** All parseable forms either produce findings or silently normalize; none is explicitly marked unsupported.

### Top TiDB Gaps

- **Parser gaps (9 forms):** Triggers, events, functions, ALTER VIEW, ALTER TABLE TTL, and ALTER TABLE LOCALITY fail at the parser level.
- **Normalized silent candidates:** RENAME TABLE, ALTER TABLE ADD/DROP INDEX, standalone CREATE INDEX, PLACEMENT POLICY, SEQUENCE, and privilege/DCL statements parse but emit no findings.
- **TiDB-specific features tracked:** PLACEMENT POLICY, SEQUENCE, TTL, LOCALITY — all parseable forms are normalized_silent except TTL and LOCALITY which are parser_error.

## Non-Goals

- Do not add or change audit rules.
- Do not change parser behavior.
- Do not claim full MySQL/TiDB/PostgreSQL DDL support.
- Do not claim dialect parity.
- Do not expand runtime database validation, catalog inspection, lock-duration estimation, or rewrite-duration estimation.
