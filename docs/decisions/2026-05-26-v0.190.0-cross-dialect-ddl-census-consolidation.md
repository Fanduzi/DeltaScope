# DR: Cross-Dialect DDL Coverage Census Consolidation

Date: 2026-05-26
Milestone: v0.190.0
Status: Active

## Context

DeltaScope started as a MySQL/TiDB tool and later added PostgreSQL. After multiple PostgreSQL DDL milestones, PostgreSQL now has deeper coverage evidence than MySQL/TiDB:

| Dialect | Census surface |
|---|---|
| PostgreSQL | 5 focused census tests: representative, completion, deep coverage, long-tail, ALTER TABLE residual |
| MySQL | 18 representative DDL forms in cross-dialect census |
| TiDB | 18 representative DDL forms in cross-dialect census |

The project cannot currently answer this question with confidence:

> Across the MySQL/TiDB DDL surface that DeltaScope intends to track, which forms are finding-covered, silently normalized, explicitly unsupported, or parser-blocked?

## Decision

Establish a consolidated DDL coverage census layer that summarizes tracked DDL coverage by dialect and by source. Add reusable summary helpers (`ddlCensusSummary`, `summarizeDDLCensusResults`, `assertArithmetic`) so that future census tests produce machine-verifiable arithmetic without hand-counting.

This milestone does not add or change audit rules or parser behavior.

## Classification Contract

Every tracked DDL form must be classified into exactly one bucket:

| Classification | Meaning |
|---|---|
| `finding_covered` | Parser/extractor/audit pipeline emits at least one finding |
| `normalized_silent` | Parser/extractor normalizes the form but no rule fires |
| `unsupported_boundary` | Parser succeeds but extractor marks the statement unsupported |
| `parser_error` | Parser or extraction fails before a supported statement can be normalized |
| `unclassified` | Test bug; should remain zero |

Arithmetic invariant: `finding_covered + normalized_silent + unsupported_boundary + parser_error + unclassified == total`
