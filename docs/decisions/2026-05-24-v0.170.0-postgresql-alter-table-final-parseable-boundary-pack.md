## Context

v0.160.0 left 4 `unsupported_boundary` and 4 `parser_error` in the PostgreSQL ALTER TABLE residual census (66 total cases). All 4 unsupported boundaries are parseable by `pg_query_go/v6` and can be promoted with conservative metadata.

v0.170.0 targets the complete remaining parseable set. After this milestone, `unsupported_boundary` reaches 0. The 4 PG18 parser-error forms remain deferred.

### Parser Dependency

Current parser: `github.com/pganalyze/pg_query_go/v6 v6.2.2`, backed by libpg_query 17. PG18 parser-error forms remain out of scope pending `pg_query_go v7`.

## Promoted Boundaries

| # | SQL form | AST shape | Risk |
|---|----------|-----------|------|
| 1 | `ALTER COLUMN full_name SET EXPRESSION AS (...)` | `AlterTableStmt` / `AT_SetExpression` / `def=AExpr` | High payload leak risk — expression body must be excluded |
| 2 | `ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY` | `AlterTableStmt` / `AT_AddIdentity` / `def=Constraint(CONSTR_IDENTITY)` | Medium sequence option leak risk |
| 3 | `ADD CONSTRAINT bookings_no_overlap EXCLUDE USING gist (...)` | `AlterTableStmt` / `AT_AddConstraint` / `def=Constraint(CONSTR_EXCLUSION)` | High operator/exclusion leak risk |
| 4 | `ALTER TABLE ALL IN TABLESPACE pg_default SET TABLESPACE fastspace` | `AlterTableMoveAllStmt` (separate top-level node) | Separate parser dispatch required |

## Parser Architecture

### Existing Path (3 cases)

`AT_SetExpression`, `AT_AddIdentity`, and `AT_AddConstraint` with `CONSTR_EXCLUSION` extend the existing `AlterTableStmt` command switch in `alterFromCmd`.

### New Top-Level Path (1 case)

`ALL IN TABLESPACE` parses as `AlterTableMoveAllStmt`, not `AlterTableStmt`. This requires:

1. A new branch for `Node_AlterTableMoveAllStmt` in the top-level PostgreSQL statement-node dispatcher.
2. A dedicated helper `extractAlterTableMoveAllStmt` in the alter extractor.

The helper returns `unsupportedStatement` if either tablespace name is missing or `objtype` is not `OBJECT_TABLE`.

## Forbidden Metadata

The following must NEVER appear in finding metadata for these rules:

| Forbidden | Applies to | Reason |
|-----------|------------|--------|
| `raw_sql` | all | Full statement leak |
| Expression body / `first_name` / `last_name` / `||` | `set_expression` | Expression payload leak |
| `sequence_options` / `start` / `increment` / `cache` / `cycle` | `add_identity` | Sequence option leak |
| `exclusions` / `operator` / `operator_class` / `room_id` / `during` / `&&` / `predicate` / `where_clause` | `add_exclusion_constraint` | Constraint shape and operator detail leak |
| `catalog_state` / `validation_result` / `dependency_graph` / `rewrite_duration` | all | Runtime validation/dependency/estimate claims |

The metadata key `has_expression` is allowed. It is a boolean-like bounded flag and must not contain the expression body.

## Deferred Scope

The 4 PostgreSQL 18 parser-error forms remain deferred:

| SQL form | Reason |
|----------|--------|
| Named `NOT NULL ... NOT VALID` | Requires PG18 parser support |
| `ALTER CONSTRAINT ... NOT ENFORCED` | Requires PG18 parser support |
| `ALTER CONSTRAINT ... INHERIT` | Requires PG18 parser support |
| `ALTER CONSTRAINT ... NO INHERIT` | Requires PG18 parser support |

Do not add string-matching workarounds for these cases.

## Public Contract / Non-Goals

DeltaScope will:
- Emit notice findings for SET EXPRESSION, ADD IDENTITY, EXCLUDE USING, and ALL IN TABLESPACE.
- Keep metadata bounded and consistent across SDK, CLI, HTTP, MCP.
- Use `AlterTableMoveAllStmt` as the parser entry for `ALL IN TABLESPACE` (not `AlterTableStmt`).

DeltaScope will not:
- Claim full PostgreSQL ALTER TABLE support.
- Claim PostgreSQL 18 parser support.
- Emit raw SQL, expression bodies, sequence options, exclusion entries, operators, or predicates in finding metadata.
- Make runtime catalog, validation, dependency, or rewrite-duration claims.

## Consequences

- After v0.170.0, `unsupported_boundary` reaches 0. All parseable PostgreSQL ALTER TABLE forms are either finding-covered or normalized silent.
- The `AlterTableMoveAllStmt` top-level dispatch path is introduced. Future `ALL IN TABLESPACE` variants (indexes, materialized views) can reuse this path.
- PG18 parser errors (4) remain blocked until `pg_query_go v7` ships.
