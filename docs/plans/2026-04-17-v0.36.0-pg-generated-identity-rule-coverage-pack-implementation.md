# v0.36.0 PostgreSQL Generated/Identity Rule Coverage Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Determine whether PostgreSQL generated/identity statements already supported by the extractor receive meaningful DDL rule coverage, and extend that coverage only through narrow, defensible rule work.

**Architecture:** Start with a rule-coverage decision gate. Characterize how supported generated/identity statements flow through the existing PostgreSQL DDL rule pipeline, identify the exact missing rule coverage, then either stop or implement the smallest viable rule applicability/coverage change. Do not re-open parser-support or shared-contract work unless the gate proves a hard blocker.

**Tech Stack:** Go, DeltaScope PostgreSQL DDL rules, rule tests, audit corpus YAML, CLI/HTTP/MCP/public Go API tests, Markdown release docs.

## Milestone Scope

**Statements in scope for coverage analysis:**
- PostgreSQL generated stored definition forms
- PostgreSQL identity definition forms
- PostgreSQL generated/identity add-column forms
- PostgreSQL generated/identity state-transition forms

**Coverage work in scope:**
- existing PostgreSQL DDL rule applicability
- narrow rule-trigger additions if clearly justified
- narrow new PostgreSQL rule IDs only if existing rules cannot express the needed signal

**Out of scope:**
- parser support widening
- shared contract widening
- generated expression evaluation
- full sequence semantics
- MySQL/TiDB rule work

- [ ] **Step 3: Run GitNexus impact before touching rule symbols**

Run:

```bash
npx gitnexus status
npx gitnexus query --repo DeltaScope "PostgreSQL DDL rules affecting alter table rewrite lock severity generated identity"
```

Then run impact on every concrete symbol you believe may need editing, for example the rule constructors or evaluators surfaced by the query.

For each candidate symbol:

```bash
npx gitnexus impact <symbol> --repo DeltaScope --direction upstream
```

Record:

- risk level
- direct callers
- affected processes
- whether any HIGH/CRITICAL warning appears

If all plausible rule-entry symbols are HIGH/CRITICAL, bias the report toward Stop unless the change is extremely narrow.
