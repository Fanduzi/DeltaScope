# v0.34.0 PostgreSQL Generated/Identity Narrow Support Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Support narrow PostgreSQL generated/identity definition forms in `CREATE TABLE` and `ALTER TABLE ... ADD COLUMN` while preserving `v0.33.0` facts and keeping generated/identity state-transition forms unsupported.

**Architecture:** First confirm the current unsupported branches are the only blockers for narrow support. Then remove generated/identity rejection from the `CREATE TABLE` and `AT_AddColumn` paths, keep fact extraction intact, lock the behavior through corpus/service/public-surface tests, and finally update release docs. Do not introduce new rules or state-transition support.

**Tech Stack:** Go, `pg_query_go/v6`, DeltaScope PostgreSQL extractor, audit corpus YAML, CLI/HTTP/MCP/public Go API tests, Markdown release docs.

## Milestone Scope

**In scope:**
- PostgreSQL `CREATE TABLE` generated stored columns
- PostgreSQL `CREATE TABLE` identity columns
- PostgreSQL `ALTER TABLE ... ADD COLUMN` generated stored columns
- PostgreSQL `ALTER TABLE ... ADD COLUMN` identity columns
- preserving `generated_when`, `is_identity`, and `identity_options`
- removing `unsupported` outcomes for these narrow forms

**Out of scope:**
- `GeneratedExpression`
- `DROP EXPRESSION`
- `SET GENERATED`
- `DROP IDENTITY`
- generated/identity-specific rules
- expression evaluation
- complete identity sequence semantics
- MySQL/TiDB behavior changes
