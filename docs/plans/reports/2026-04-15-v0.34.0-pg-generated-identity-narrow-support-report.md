## Current Unsupported Behavior

Rejection happens in two locations:

1. **`hasUnsupportedColumnConstraint`** (extractor.go:484-506): Called for both `CREATE TABLE` column loop (line 87) and `ALTER TABLE AT_AddColumn` (line 366). Returns `UnsupportedDetail` with `generated_column` or `generated_as_identity` feature name and `generatedIdentityUnsupportedMetadata` carrying facts.

2. **Dead-code identity checks**: Lines 84 (`extractCreateStmt`) and 369 (`alterFromCmd`) check `column.GetIdentity()` which always returns `""` for identity columns parsed by `pg_query_go/v6`. These branches never fire for the standard identity syntax.

The actual rejection is exclusively in `hasUnsupportedColumnConstraint`. Facts are preserved in `Unsupported.Metadata` via `generatedIdentityUnsupportedMetadata` (lines 575-596).

## Task 2 Decision

**Proceed.**

All four conditions for Proceed are satisfied:

1. Required facts (`generated_when`, `is_identity`, `identity_options`) are stable and present in `Unsupported.Metadata` today.
2. The unsupported outcome is caused solely by explicit rejection in `hasUnsupportedColumnConstraint`, not by missing facts.
3. Task 2 can be completed with a minimal extractor patch — no refactoring of the PostgreSQL extraction flow is needed.
4. State-transition forms (`DROP EXPRESSION`, `SET GENERATED`, `DROP IDENTITY`) are handled by separate `AT_DropExpression`, `AT_SetIdentity`, and `AT_DropIdentity` subtype cases in `alterFromCmd`, which are completely independent of the `AT_AddColumn` path.

## Approved Production Scope For Task 2

Task 2 is allowed to modify only `internal/infrastructure/parser/postgresql/extractor.go` with the following minimal changes:

1. **`extractCreateStmt`** (lines 82-92): Remove the generated/identity rejection for narrow definition forms. Specifically:
   - Remove the dead-code `column.GetIdentity()` check at line 84.
   - In `hasUnsupportedColumnConstraint`, stop returning unsupported for `CONSTR_GENERATED` and `CONSTR_IDENTITY` when they appear in `CREATE TABLE` column definitions.
   - After removing the rejection, `columnFromDef` will be called, which already calls `applyGeneratedIdentityFacts`, so facts will automatically land on `spec.Column`.

2. **`alterFromCmd`** `AT_AddColumn` case (lines 361-372): Remove the generated/identity rejection for narrow definition forms. Specifically:
   - Remove the dead-code `column.GetIdentity()` check at line 369.
   - In the `hasUnsupportedColumnConstraint` call, narrow the check to no longer reject `CONSTR_GENERATED` and `CONSTR_IDENTITY` for `AT_AddColumn`.
   - After removing the rejection, `columnFromDef` will be called for add-column, populating `Alter.Column.Definition` with facts.

3. **`hasUnsupportedColumnConstraint`** (lines 484-506): This is the central gate. Task 2 should either:
   - Remove the `CONSTR_GENERATED` and `CONSTR_IDENTITY` cases entirely (since state-transition forms are handled separately), or
   - Add a parameter to distinguish definition forms from state-transition forms (though state-transition forms don't go through this function, so removing the cases is simpler).

4. **No other changes**: The `AT_DropExpression`, `AT_SetIdentity`, and `AT_DropIdentity` cases must remain unchanged. `applyGeneratedIdentityFacts`, `identityOptionsFromConstraint`, and `generatedIdentityUnsupportedMetadata` must not be modified.

5. **Test updates**: Convert characterization tests to supported-behavior tests (remove unsupported assertions, add `DDL.Columns`/`Alter.Column.Definition` fact assertions). State-transition unsupported tests must remain unchanged.

## Explicit Deferrals

State-transition forms that must remain unsupported:

- `ALTER TABLE ... ALTER COLUMN ... DROP EXPRESSION` — feature `"generated_column"`, handled by `AT_DropExpression`
- `ALTER TABLE ... ALTER COLUMN ... SET GENERATED ...` — feature `"generated_as_identity"`, handled by `AT_SetIdentity`
- `ALTER TABLE ... ALTER COLUMN ... DROP IDENTITY` — feature `"generated_as_identity"`, handled by `AT_DropIdentity`

These are separate `AlterTableType` cases and are not affected by changes to `hasUnsupportedColumnConstraint` or the `AT_AddColumn` path.
