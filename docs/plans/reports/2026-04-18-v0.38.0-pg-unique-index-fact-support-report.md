## Rule Applicability

| Rule family | CREATE TABLE unique | CREATE INDEX secondary | CREATE UNIQUE INDEX | Decision |
|-------------|---------------------|------------------------|---------------------|----------|
| `ddl.index.secondary.prefix.require` | N/A (secondary only) | FAIL: AppliesTo=false | N/A | Gap: `appliesToCreateTableIndexes` excludes `DDLOperationCreateIndex` |
| `ddl.index.unique.prefix.require` | PASS | N/A | FAIL: AppliesTo=false | Gap: same gate |
| `ddl.index.columns.max_count` | PASS | FAIL: AppliesTo=false | FAIL: AppliesTo=false | Gap: same gate |
| `ddl.index.total.max_count` | PASS | FAIL: AppliesTo=false | FAIL: AppliesTo=false | Gap: same gate |
| `ddl.index.duplicate.forbid` | PASS | FAIL: AppliesTo=false | FAIL: AppliesTo=false | Gap: same gate |
| `ddl.index.redundant.left_prefix.forbid` | PASS | FAIL: AppliesTo=false | N/A | Gap: same gate |
| `ddl.index.redundant.unique_overlap.forbid` | PASS | N/A | N/A | Gap: same gate |

Root cause: All generic index rules delegate to `appliesToCreateTableIndexes()` which checks `statement.DDL.Operation == DDLOperationCreateTable`. Standalone `CREATE INDEX` produces `DDLOperationCreateIndex`, which is filtered out.

## Task 2 Decision

**Proceed.**

Rationale:
1. Parser/extractor facts are fully stable for all 7 supported forms — typed AST produces correct `spec.Index` with `Name`, `Kind`, `Columns`, and `Options["concurrently"]`.
2. The applicability gap is a single gate function (`appliesToCreateTableIndexes`) that can be extended or supplemented with a parallel gate (`appliesToCreateIndexStatements`) without touching rule evaluation logic.
3. No public spec widening required — `spec.Index`, `spec.DDLOperation`, `spec.IndexKind` already have the necessary types.
4. No expression/partial/include/operator-class/nulls semantics needed for the approved scope.
5. Each rule family can be covered by corpus cases (naming, count, duplicate, redundancy).
6. PostgreSQL Docker-backed e2e paths can verify user-facing findings.

## Approved Production Scope For Task 2

1. Add `appliesToCreateIndexStatements()` helper in `internal/domain/rule/ddl/common.go` that returns true for `DDLOperationCreateIndex`.
2. Extend each generic index rule's `AppliesTo()` to include `appliesToCreateIndexStatements(statement) || appliesToCreateTableIndexes(statement)` (or introduce a unified `appliesToIndexStatements` gate).
3. Rule evaluation logic is unchanged — only applicability gate expansion.
4. No new rule IDs. No policy default changes.

## Explicit Deferrals

- Expression index rendering (`lower(email)` etc.)
- Partial index predicate semantics (`WHERE ...`)
- INCLUDE clause semantics
- Operator class / access method / storage parameters
- NULLS NOT DISTINCT semantics
- Concurrent index build semantics (build-mode auditing)
- ALTER TABLE ... ADD UNIQUE CONSTRAINT (separate from CREATE INDEX)
- Any new rule IDs or policy default changes
