# DeltaScope v0.31.0 Release Notes

Release date: 2026-04-14

## Summary

DeltaScope `v0.31.0` is the **PostgreSQL ALTER TABLE GENERATED Follow-up Pack**. It maps additional PostgreSQL generated/identity `ALTER TABLE` forms to explicit unsupported feature tags. This is boundary tightening only — it does not represent generated-column support, identity-column support, or complete PostgreSQL `ALTER TABLE` support.

## What Changed

`v0.30.0` locked PostgreSQL `ALTER TABLE ... ADD COLUMN` generated/identity forms to explicit unsupported features. `v0.31.0` closes the adjacent gap by mapping the remaining generated/identity alteration forms that `v0.30.0` intentionally left on generic unsupported boundaries:

```sql
ALTER TABLE users ALTER COLUMN full_name DROP EXPRESSION;
ALTER TABLE users ALTER COLUMN id SET GENERATED BY DEFAULT;
ALTER TABLE users ALTER COLUMN id DROP IDENTITY;
```

These statements now return explicit unsupported outcomes instead of generic AST-subtype names.

## Exact Unsupported Mappings

| Shape | Unsupported feature |
|-------|---------------------|
| `ALTER TABLE ... ALTER COLUMN ... DROP EXPRESSION` | `generated_column` |
| `ALTER TABLE ... ALTER COLUMN ... SET GENERATED ...` | `generated_as_identity` |
| `ALTER TABLE ... ALTER COLUMN ... DROP IDENTITY` | `generated_as_identity` |

### v0.30.0 context (already locked)

| Shape | Unsupported feature |
|-------|---------------------|
| `ALTER TABLE ... ADD COLUMN ... GENERATED ALWAYS AS (...) STORED` | `generated_column` |
| `ALTER TABLE ... ADD COLUMN ... GENERATED ALWAYS AS IDENTITY` | `generated_as_identity` |

## Surface Contract

Surface behavior remains consistent with the existing unsupported contract:

- **CLI** and **`pkg/deltascope`** return partial results with an `unsupported` array and `ErrUnsupportedStatement`.
- **HTTP** and **MCP** expose unsupported statements as transport-level errors because the underlying audit call returns an error.

This release locks the boundary contract across all confidence layers:

- SQL corpus coverage for each new boundary form
- Service-level table-driven checks
- Surface parity for CLI, HTTP, MCP, and `pkg/deltascope`

## What Did Not Change

- DeltaScope does not model generated expressions or identity semantics as supported features.
- DeltaScope does not support generated-column alteration.
- DeltaScope does not support identity-column alteration.
- DeltaScope does not provide complete PostgreSQL `ALTER TABLE` support.
- No new rule IDs, CLI flags, or public API types were added.
- No parser dependency or package version was changed.
- MySQL and TiDB audit behavior is unchanged.
- `v0.26.0` PostgreSQL `CREATE TABLE` unsupported boundaries remain in place.
- `v0.30.0` PostgreSQL `ALTER TABLE ... ADD COLUMN` unsupported boundaries remain in place.

## Follow-up / Next Decisions

- Decide whether future PostgreSQL boundary work should deepen explicit unsupported subtyping for additional alter-table forms (e.g., `ALTER COLUMN ... SET DATA TYPE`, `ALTER COLUMN ... RESTART`) or stay on generic unsupported contracts.
- Decide later whether these explicit unsupported boundaries should ever become real generated-column or identity-column support.
