# DeltaScope v0.36.0 Release Notes

## Summary

DeltaScope v0.36.0 is the **PostgreSQL Generated/Identity Rule Coverage Pack**. Three new PostgreSQL-only forbid rules now cover the generated/identity state-transition forms that became supported in v0.35.0, so those forms produce explicit `rule_id` findings instead of passing silently.

This is rule coverage — not parser support widening, not spec contract widening, not generated expression evaluation, not complete PostgreSQL sequence semantics.

## What Changed

### New Rule Coverage

Three PostgreSQL-only forbid alter-action rules are now registered:

| Rule ID | Action | Covered Form |
|---------|--------|-------------|
| `ddl.alter.drop_expression.forbid` | `drop_expression` | `ALTER TABLE ... ALTER COLUMN ... DROP EXPRESSION` |
| `ddl.alter.set_generated.forbid` | `set_generated` | `ALTER TABLE ... ALTER COLUMN ... SET GENERATED ...` |
| `ddl.alter.drop_identity.forbid` | `drop_identity` | `ALTER TABLE ... ALTER COLUMN ... DROP IDENTITY` |

These rules use the existing `newForbiddenAlterActionRule` constructor with a PostgreSQL-only dialect allowlist — the same pattern as the five existing PG-native alter action forbid rules (`set_data_type`, `set_default`, `drop_default`, `set_not_null`, `drop_not_null`).

### Surface Coverage

CLI, HTTP, MCP, and `pkg/deltascope` surfaces now produce explicit `rule_id` findings for these forms. Example JSON shape:

```json
{
  "findings": [
    {
      "rule_id": "ddl.alter.set_generated.forbid",
      "level": "blocker",
      "message": "ALTER action 'set_generated' is not allowed"
    }
  ]
}
```

### Supported State-Transition Forms Covered

| Form | Rule ID |
|------|---------|
| `ALTER TABLE ... ALTER COLUMN ... DROP EXPRESSION` | `ddl.alter.drop_expression.forbid` |
| `ALTER TABLE ... ALTER COLUMN ... SET GENERATED ALWAYS` | `ddl.alter.set_generated.forbid` |
| `ALTER TABLE ... ALTER COLUMN ... SET GENERATED BY DEFAULT` | `ddl.alter.set_generated.forbid` |
| `ALTER TABLE ... ALTER COLUMN ... DROP IDENTITY` | `ddl.alter.drop_identity.forbid` |

### What Did Not Change

- No parser support widening — supported state-transition forms were already supported in v0.35.0.
- No spec contract widening — no new spec fields.
- No generated expression evaluation.
- No complete PostgreSQL sequence semantics.
- No MySQL/TiDB behavior changes.
- No new CLI flags.

```bash
  DELTASCOPE_VERSION=v0.36.0 sh
```
